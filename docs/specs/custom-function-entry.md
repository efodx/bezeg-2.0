# Custom formulas for root-finding Demonstrations

**Status** — specification. Bisection is the pilot. Newton and Secant are the second consumer on their shared route. See [sequencing](#sequencing).

## Teaching workflow and scope

A teacher opens the ordinary Bisection Demonstration at `/bezeg-2.0/analysis/bisection`, enters `cos(x) - x`, applies it, and sets the bracket to `[0, 1]`. They show the midpoint and the retained half using the existing step controls. They save the setup as a Preset, reopen it, and can export it to a file and import it on another browser. On `/bezeg-2.0/analysis/root-finding`, they use the same formula with a Newton starting point or two Secant starting points and show the corresponding tangent or secant steps. Both routes support teaching the mathematical idea directly in free exploration. Guided examples remain independently authored activities for students. See [independent study and classroom teaching](../guardrails.md#independent-study-and-classroom-teaching).

This specification covers one real-valued formula in one variable, on these two existing routes. Later work may consider parameters, multiple formulas, sequences, differential equations, parametric and polar inputs, and additional routes. Authoring guided scenes with formulas and adding a symbolic algebra workspace are separate work.

## Editing and state

- Keep the existing built-in chooser and add a shared formula field with a labelled **Apply** action in free exploration. Selecting the custom entry opens the editor. Typing and blurring are draft edits. Apply, including keyboard activation, validates the complete text and makes one graph-owned commit on success. The plot, construction, readouts, saved state and any running iteration continue to use the committed function while the field is being edited.
- For a rejected draft, retain the text for correction, give a useful reason in Slovenian and English, and keep the graph model and playback at their current settings. Identify empty input, unsupported syntax or names, and exceeded limits. Use the shared control conventions for focus and accessible error announcements. Runtime mathematical outcomes such as an undefined endpoint have their own status and recovery guidance.
- An accepted formula retains the current bracket or starting guesses, returns the run to step zero and stops playback. A valid formula can be applied when the current bracket or starting guesses are unsuitable. Show the relevant status and keep those controls editable so the teacher can repair the setup. A committed endpoint, guess or method change resets the run according to the existing graph rules. Switching to a built-in restores that selector's existing setup behavior and clears the formula draft and its error.
- Run Reset returns to step zero with the current committed function and parameters and stops playback. Workspace Reset follows the shared default or selected Preset behavior. Workspace Reset, Preset restore and scene replacement resync the field to the incoming committed state and clear draft errors. Restore the pre-lesson committed state on early exit or return through the existing checkpoint path, including formula, parameters, step and view. Completion follows the existing lesson lifecycle and retains its final authored scene. Reopening a Preset or restoring a checkpoint leaves playback paused.
- Store the formula as serializable source text with a distinct custom-function case in the graph's model. Preserve built-in IDs, legacy Presets, routes and authored scene payloads. Save the committed function and the graph's existing run data. Parse and validate saved or imported source against the same limits before applying it. Reject an unsupported formula with an actionable import error and leave the existing graph and affected Preset collection intact. Compiled expressions, derivatives, drafts and playback timers are transient.

## Shared formula support

The parser and evaluator are independent of React, JSXGraph and the individual graphs. Compile accepted input into a reusable evaluator of a finite real value at a finite `x`, or a typed undefined/out-of-domain result. Expose symbolic differentiation as an optional capability for Newton. Keep library types inside the formula module. The graphs own the iteration, domain and bracket rules, drawing and readouts. Derive compiled state from the committed source and reuse it across samples and steps. Rebuild it when the source changes or a restored source needs compilation.

Start with an allowlist of decimal numbers, `x`, `pi`, `e`, parentheses, unary `+` and `-`, arithmetic `+ - * / ^`, and single-argument `sin`, `cos`, `tan`, `exp`, `log` (natural log) and `sqrt`. Use explicit multiplication and a decimal point in source, with bilingual examples and help. Define precedence, associativity and real-domain semantics before wiring the field. Bound source length before parsing and bound depth and expression size before evaluation, including the derivative's work and output. Accept only allowlisted expression nodes and calls. Assignments, extra variables, property access, indexing, arrays, statements and arbitrary code are rejected on both typed and imported paths. A syntactically valid expression can be undefined at some real arguments. Reject complex, non-finite or non-numeric results at evaluation time and keep them out of graph primitives.

Math.js is a candidate because it exposes parsed expressions, compilation, symbolic differentiation and selective bundles. Its full parser accepts a wider language than this feature. Review the installed version and its dependency graph, define and test the allowlist before compiling, and measure production chunks with the actual parse/evaluate/derivative subset. Record incremental raw and compressed bytes for both routes and check the effect on initial shell and unrelated routes. Compare with a small dedicated evaluator and bounded derivative rules if the candidate adds substantial cost or weakens the grammar boundary. Nerdamer is a symbolic comparison point. Record the choice and measurements before selecting a dependency. [Math.js parsing](https://mathjs.org/docs/expressions/parsing.html), [security](https://mathjs.org/docs/expressions/security.html), [derivative](https://mathjs.org/docs/reference/functions/derivative.html), [custom bundling](https://mathjs.org/docs/custom_bundling.html), [Nerdamer differentiation](https://nerdamer.com/docs/reference/diff/).

## Mathematical behavior

### Bisection

- Use the existing graph-owned iteration for the sign test, midpoint and retained half. Separate a zero evaluated at an endpoint or midpoint, a bracket with opposite endpoint signs, and a bracket on which continuity is established. Use a root guarantee and its corresponding error bound only where the continuity and sign conditions are established. Establish continuity for `cos(x) - x` from its operations. For an unknown continuity case, allow the sign-based construction with a clear qualification and label interval width as such. Finite samples and a shrinking interval alone cannot establish continuity or a root.
- If a required endpoint or midpoint is undefined or non-finite, stop playback before advancing and explain how to adjust the bracket or formula. A detected discontinuity or pole inside the bracket invalidates a custom root bracket even when both endpoints evaluate to finite numbers of opposite sign. Draw detected breaks as gaps. Cover `1/x` on `[-1, 1]` and the off-midpoint pole of `1/(x - 0.3)` on `[0, 1]`. Treat more general cases conservatively when continuity or a suspected break cannot be established. Preserve the built-in jump example and its intentional illustration of the failure of the continuity hypothesis.

### Newton and Secant

- Newton requests and compiles the symbolic derivative once per accepted custom function when needed, then reuses the existing Newton iteration and tangent construction. A valid function with an unavailable derivative remains usable in Secant. Give Newton an explicit stop reason when the derivative is unavailable or undefined at the current point, the slope is zero, or an iterate or required evaluation is outside the supported finite real domain. Check the original function's domain even when derivative simplification widens it.
- Secant uses only function values and the existing two-start iteration. Handle a zero secant denominator or an invalid evaluation or iterate through the same stopped-run behavior. Manual steps and playback use the same transition. Keep the last valid construction and omit invalid points or lines.
- Retain built-in reference-root readouts. For custom functions omit the reference-root marker and error against a reference root when that root is unknown. Use applicable observables such as the residual or the step size with distinct labels.

## Acceptance and verification

1. **Bisection pilot.** In ordinary exploration, Apply `cos(x) - x`, set `[0, 1]` using the controls, and show a first midpoint of `0.5` with retained bracket `[0.5, 1]`. Verify the later estimate against the known zero near `0.7390851332`. Check built-in continuous and jump examples, same-sign endpoints, an endpoint zero, an invalid midpoint, and both an aligned and a shifted pole. For example, `1/x` on `[-1, 1]` and `1/(x - 0.3)` on `[0, 1]` must never report a converged root or connect across the detected break. Check that an unestablished continuity case uses conditional language even when its samples are finite.
2. **Newton and Secant.** With the same formula, check Newton from `1` against `x - f(x)/f'(x)` and Secant from `0` and `1` against the two-point update. Assert the displayed tangent or secant, iterations near the known zero, and omission of unknown reference error. Cover derivative unavailability, an undefined derivative (`sqrt(x) + 1` at `0`), zero slope on a nonzero residual, a zero Secant denominator, and an iterate that leaves the real domain. Check that Secant works with the derivative path unavailable and that the existing built-in readouts still work.
3. **Formula boundary and state.** Unit-check precedence, accepted names, real-domain outcomes, limits and rejection of executable or unsupported syntax. Exercise Apply, invalid Apply during playback, switching built-in/custom and Newton/Secant, run and workspace Reset, paused Preset reopen, exported file reimport in a clean browser, and invalid import rollback. Check a legacy built-in Preset on both routes and authored lesson entry, stepping, early exit and return with a pre-lesson custom formula. Verify the restored values on the board and in the controls.
4. **Browser and presentation.** Use production browser smoke on the affected routes and their existing guided flows when implementing each slice. Verify both languages, useful error/status announcements, keyboard and touch operation, a narrow browser, and a readable free-exploration graph and reachable teaching controls in Presentation mode. Keep existing scene, keyboard and viewport regression coverage for guided lessons. Check dependency measurements before accepting the pilot, and record mathematical, persistence and browser evidence for each route.
