# Codex worker budget monitoring

## Scope and boundary

Implement the Codex monitoring branch of the [context budget trial](agent-workflow-evaluation.md#context-budget-trial--2026-10-24), following the [live control probe](../agent-workflow/codex-handoff-probe-2026-10-24.md). User authorized implementation and live verification on 2026-10-24. This is developer tooling, with no application behavior changes.

A local Node watcher automatically detects when recorded request input reaches the handoff threshold. The handler consumes its structured event and sends `HANDOFF` through Codex collaboration tools. The watcher cannot itself invoke those hosted tools. This is cooperative budget enforcement, not a hard cap: telemetry and message delivery lag, and a single request can overshoot. The existing 150k budget and 15k signal margin remain trial settings, not a proven Codex safety bound.

## Acceptance

1. A dependency-free Node CLI identifies one child by exact parent thread ID plus canonical agent path (parent defaults from `CODEX_THREAD_ID`). Read session metadata, not filenames alone. An explicit sessions-root option supports fixtures and installations; default is `CODEX_HOME/sessions` or `~/.codex/sessions`. Ambiguous matches fail rather than targeting another worker.
2. Read `event_msg/token_count` at `payload.info.last_token_usage.input_tokens`. Count cached input once; ignore cumulative totals and null/malformed usage. Preserve a threshold crossing within a batch even if a later usage sample drops after compaction. Never emit a threshold event from another thread.
3. Default trigger is budget 150000 minus margin 15000; allow a positive explicit threshold for testing. Validate polling and timeout arguments. Emit one JSON terminal event with identity, observed request input, threshold and rollout path. Distinguish `handoff_required`, `completed`, `unavailable`, `idle`, and `error`, with documented exit codes. A completed current turn must not request a handoff. At discovery, select the latest turn so historical completion/crossing events do not affect a resumed worker. Stop on completed/aborted worker turns; one invocation watches one worker turn.
4. Follow a growing rollout incrementally, tolerate incomplete trailing JSON until newline, skip malformed complete records, bound missing/no-telemetry and idle waits, and fail clearly on unreadable or unsupported telemetry. Poll only the selected rollout once discovered. Read-only: no mutations to sessions, worker files, or processes.
5. Focused automated tests exercise wrong-parent/path isolation, cumulative-vs-request input, exact crossing, crossing followed by lower input, split JSON writes, missing/ambiguous/unreadable telemetry, completion, idle, and CLI validation. A deliberate metric mutation must produce an observed regression failure. Keep test artifacts in temporary directories.
6. Live synthetic verification launches a worker below a chosen threshold, observes its growing rollout cross that threshold without manual threshold selection afterward, relays the emitted handoff request, and checks a partial note preserves progress. Record detection/input overshoot and limitations; no claim of a verified 150k ceiling or usage savings.
7. Document the exact watcher command and handler relay, including background-command polling (process exit alone is not a guaranteed agent wakeup), event-specific behavior, telemetry failures and cleanup. Update dispatch guidance without changing model defaults or the worker brief. Record results in repository evidence and the evaluation log.

## Verification

Use Node's built-in test runner for the watcher; no production app build or browser smoke applies. Handler owns integration/docs, stable-checkpoint review, live relay and Git. Delegate watcher implementation/tests to one bounded worker. Independent review covers tooling correctness and workflow constraints.

## Verified result — 2026-10-24

- Handler captured task start at 09:31:21 UTC. Implementer and independent reviewers used fresh contexts with requested GPT-6 Luna High. Node 24.21.0 was available; the Python alias did not execute, so the implementation uses the project's Node runtime without dependencies.
- All 12 focused tests passed after independent review. Substituting cumulative input for request input caused the metric assertion to fail (`999999 !== 20`). The reviewer found a mixed-marker resumed-turn bug; the added fixture failed before repair (`completed` instead of `idle`), then passed. Re-review closed that finding with no residual actionable defects. Logs remain under `.command-logs/codex-worker-watch-*.log`.
- The live worker `/root/automatic_budget_probe` had a threshold of **46000 selected before dispatch**. It generated numeric payloads in up to twelve sequential steps with six-second pauses, preserving nonce `ELDERFLOWER-AUTO-463`. Its first measured request input was 34433. Steps 1–8 summarized output; a clarification required subsequent outputs to be surfaced with `text(result.output)` so they actually grew context. The threshold was unchanged.
- The watcher process, polling every 0.2 seconds, emitted exactly one `handoff_required` event at 46864 request-input tokens (864 above the trigger), targeting the correct parent and child. The handler consumed the yielded process output and relayed `HANDOFF` with `send_message`. The worker stopped after step 11, wrote its correct nonce/progress/one remaining step to `.command-logs/codex-automatic-handoff.md`, and returned partial. Final recorded input was 52009, 6009 above the trigger. This includes the handler relay delay and handoff-note response, not just watcher polling.
- A fresh watcher attached after the probe completed returned `completed` despite historical threshold crossing. A separate default-threshold watcher on the resumed correctness reviewer returned `completed`, 53371 input against 135000, with no handoff. Both retained process handles completed; no monitor was left running.
- The final suite and syntax checks passed locally on Windows. Developer tools CI now includes the watcher suite on Windows and Linux; remote CI outcome is separate from local verification. Documentation links and whitespace were checked. No application behavior, routes, mathematical operations or localization changed, so no app build or browser smoke was required.

This verifies automatic detection plus a handler relay, including a real below-to-above crossing. It does not establish hard enforcement, a universal 15k margin, behavior at 150k, savings, compaction quality, or safe cancellation of arbitrary external processes. The handler still needs to consume watcher output promptly. No hosted collaboration API is exposed to the shell watcher; a fully autonomous process-to-agent interrupt would require a separately supported control integration.

## Handler overhead follow-up

The owner requested handler-cost accounting after implementation. The watcher itself has no model calls; its surrounding orchestration can be expensive. The following observed handler request usage comes from this chat's local rollout `token_usage_record.payload.usage`, associating each selected tool-generating response with its following usage record. Only the live synthetic watcher's launch/polls (process session 22324, execution cells 31/32) and the final handoff relay were selected, between 09:36:56 and 09:39:03 UTC on 2026-10-24. Development, review-worker dispatch, probe correction, and later evidence analysis are excluded.

| Watcher launch, dedicated polls and cell resumes | 6 | 647624 | 646144 | 497 |
| Handoff relay | 1 | 112236 | 111872 | 93 |
| Polling combined with source review or live inspection | 4 | 438326 | 436608 | 870 |

The dedicated monitoring plus relay group totals **759860 input, 758016 cached, 1844 uncached, and 590 output tokens**. Including all mixed responses gives 1198186 input and 1460 output, but that overattributes useful work to monitoring. These are observed requests, not a counterfactual marginal-cost measurement or a final bill; later rereading of the added polling history is not included. Cached tokens are a subset of input, not extra tokens.

Handler turn configuration recorded GPT-6.1 Sol. At the published Standard credit rates checked on 2026-10-24 (50/2.5/250 credits per million uncached input/cached input/output), the dedicated group plus relay illustrates **2.135 credits**, or **3.530** if every mixed response is included. Actual account deductions and included subscription limits cannot be inferred from these calculations. The synthetic Luna worker's entire recorded usage (1053895 input, 1015680 cached, 2573 output) illustrates 0.382 credits at its 2.5/0.25/12.5 rates. This is not a comparable useful-task benchmark, but it shows why a stronger handler's extra round trips can outweigh cheaper-worker savings. Sources: [credit pricing](https://learn.chatgpt.com/docs/pricing), [usage semantics](https://developers.openai.com/api/docs/guides/agents-api/observability).

The handler procedure now batches idle process waits within a tool execution rather than specifying one model round trip per five-second poll, and prefers checks alongside useful work. This is an overhead-reduction recommendation, not a measured savings result. Future trial acceptance must include handler launch/poll/resume/relay costs, worker handoff/fresh-context setup, and avoided worker usage with model/cache weighting; worker input peaks alone cannot establish a net gain. No new live synthetic run was incurred solely for this retrospective analysis.
