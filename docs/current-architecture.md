## App shell and deployment

The manifest declares React 18, TypeScript 4.9, React Router 6, Bootstrap 5, React Bootstrap 2, JSXGraph 1.9, and Create React App's `react-scripts` 5. These are declared dependency ranges, not a claim about every resolved package version.

[`src/index.tsx`](../src/index.tsx) creates a browser router from [`src/Routes.tsx`](../src/Routes.tsx) and mounts it in React Strict Mode. Routes and navigation explicitly include `/bezeg-2.0`. [`src/AppHeader.tsx`](../src/AppHeader.tsx) provides the shared brand row, a link to the dedicated demonstrations page, and real compact language selector on every app page. [`src/App.tsx`](../src/App.tsx) supplies selected-preset, presentation-mode, and active demonstration workspace metadata through `SiteContext`. Prototype variants are archived at commit `1a90bf1`; query parameters no longer swap headers.

[`package.json`](../package.json) sets `homepage` to `/bezeg-2.0`. Its `build` script creates a production bundle; its separate `deploy` script publishes `build` to the explicit remote `https://github.com/efodx/bezeg-2.0.git` using `gh-pages`, with `predeploy` running the build first. The separate site was published on 2026-10-09 at `https://efodx.github.io/bezeg-2.0/`; Pages serves the root of its `gh-pages` branch. See [release verification](reviews/separate-project-site.md). The original site's `/bezeg/` route and repository are independent and are not targeted by this release copy.

[`public/404.html`](../public/404.html) redirects a missing path into an encoded query while retaining the project path segment. [`public/index.html`](../public/index.html) restores that path with `history.replaceState` before React starts. Both scripts attribute the MIT-licensed `rafgraph/spa-github-pages` approach. Routing, asset base paths, and this redirect pair must be considered together when changing hosting or tooling.

The HTML loads MathJax 3 from a CDN. Static hosting does not currently imply fully self-contained or offline operation.

## Demonstration metadata

[`src/demonstrations.ts`](../src/demonstrations.ts) owns the explicit, ordered catalog: identities, exact paths, families, role-specific titles, prompt pairs, navigation actions, and starting selections. Its two queries, `getDemonstrationCatalog()` and `findDemonstration(pathname)`, return fresh localized values through the existing localization module. Catalog, workspace, prompts, and app context consume these queries instead of importing the router. Catalog titles and actual graph headings remain distinct where they differed before. Illustrations and graph-specific descriptions stay with their existing owners.

[`src/Routes.tsx`](../src/Routes.tsx) is the routing adapter: a typed exhaustive graph map binds each Demonstration identity to its existing graph implementation, and metadata supplies the route paths. Home and catalog remain separate routes. Unknown exact metadata paths return absence; the router retains its error view. Geometry, preset identifiers, and board lifetime are unchanged. This release uses the new `/bezeg-2.0/` public base. See [the metadata spec](specs/demonstration-metadata.md).

## Guided lessons

The repository now contains a bounded Guided lesson runtime for eight demonstrations: the ordinary Bézier curve, De Casteljau construction, rational De Casteljau construction, degree elevation, cubic and quintic PH curves, the base rational Bézier curve, and affine transformations. `LearningPrompt` remains the lightweight free-exploration prompt; the lesson runtime adds a graph-cell-sized overlay with explicit explanation, calculation, and observation frames. Explanation frames cover the coordinate system while keeping the graph temporarily non-interactive; observation frames fade the overlay out to a compact, pointer-transparent graph-side prompt, positioned at the graph's top center by default and movable by pointer drag or keyboard arrows while keeping the complete prompt inside the full JSXGraph coordinate-system rectangle. **Nadaljuj učno pot** / **Continue lesson** fades the full overlay back in at the current observation frame. **Naprej** is the only forward lesson command, with **Nazaj** and **Naprej** rendered as narrow, full-height vertical edge rails without arrow glyphs. There is no separate Reset control; moving backward through the lesson reapplies earlier scenes. Exit remains session-only and is a close icon with an accessible label. Lesson copy uses TeX delimiters for inline and display mathematics; `GuidedLesson` delegates typesetting to the existing MathJax loader and clears stale output before re-typesetting a changed frame, visibility, or language. Existing direct graph links remain the default, while the catalog and graph workspace expose an optional Learn entry for the exact availability allowlist.

Static content lives in [`src/learning/content/guidedLessons.ts`](../src/learning/content/guidedLessons.ts), separate from route metadata and graph classes. The runtime adapts that content through [`src/learning/runtime/lessonCatalog.ts`](../src/learning/runtime/lessonCatalog.ts) into a narrow typed capability interface. Demonstration-owned adapters retain responsibility for cache invalidation, board updates, auxiliary-object lifecycle, and mathematical meaning. Lesson scenes capture and restore in-memory graph state and do not write Presets. De Casteljau exposes explicit Play/Pause/Replay controls in its observation frame; the graph-owned animation runs one pass from the current parameter to `t = 1`, never autoplays or loops in lesson mode, and is stopped before scene restoration, navigation, exit, route changes, and disposal. The pilot copy and formulas are implementation-ready drafts, but owner/subject-matter review and classroom/device review remain open. See [ADR 0002](adr/0002-guided-lessons-static-content-and-graph-capabilities.md), [ADR 0003](adr/0003-frame-based-graph-anchored-lesson-overlay.md), and the [runtime](tasks/guided-lessons/implement-guided-lesson-runtime.md) and [content](tasks/guided-lessons/study-and-fill-pilot-content.md) tasks.

## Geometry and interactive graphs

[`src/bezeg`](../src/bezeg) holds point and curve APIs and mathematical implementations. [`src/graphs/curves/object`](../src/graphs/curves/object) adapts those objects to JSXGraph, including drawing, selection, transforms, controls, and serialization.

Editable polynomial, rational and spline inputs now use numeric `PointImpl` objects. [`ModelPointBinding`](../src/graphs/curves/object/ModelPointBinding.ts) copies drag coordinates into the model and mirrors model changes into the adapter's board point. Replacing or deleting inputs disposes those bindings by identity. Function-backed points remain for dependent spline/PH constructions; this does not change evaluation, sampling or the shared cache revision. PH generating `w` inputs also stay numeric while their auxiliary editor owns bindings.

[`GraphSession`](../src/graphs/base/GraphSession.ts) owns the main board's lifetime, board subscriptions, resize observer, abort signal and coalesced drag-refresh timers. Graph disposal is unconditional; readiness accounts for initialization, deferred refreshes and explicit scene transitions. Graph classes and adapters still own their mathematical constructions and commands. This is the first [ownership foundation](specs/curve-ownership-refactor.md), with wider scene, command and preset-codec migration still outstanding.

[`BaseGraph`](../src/graphs/base/BaseGraph.tsx) is a React class component responsible for initializing a JSXGraph board, loading default or saved presets, arranging tools and commands, and exporting images. [`BaseCurveGraph`](../src/graphs/base/BaseCurveGraph.tsx) adds board pointer events, selection, point editing, and curve serialization. Individual demonstrations derive from these bases or related specializations.

All 26 active graph routes use [`DemonstrationWorkspace`](../src/graphs/base/DemonstrationWorkspace.tsx), composed through `BaseGraph`/`BaseCurveGraph` and Demonstration metadata in `SiteContext`. The shell separates topic navigation, graph, and persistent **Uredi**, **Prikaz**, and **Shrani** inspector sections; the narrow layout places a collapsible inspector after the graph. Presentation and pan/zoom controls are explicit. Route-specific graph and selected-curve command builders remain in **Uredi**; shared and per-curve visibility controls are in **Prikaz**; preset and image export controls are in **Shrani**. Structured coordinate editing is used on the general Bézier and PH workflows, with a hodograph editor for PH curves. Other routes retain their existing command builders, including spline-derived point constraints. [`JGBox`](../src/JGBox.tsx) still supplies the board's fixed element ID. A ResizeObserver adapts all workspace boards to their container, and the workspace routes free their boards on unmount. Legacy presentation CSS remains for non-workspace contexts.

## State and persistence

State is spread across React component state, React contexts, mutable curve/board objects, and singleton contexts under [`src/graphs/context`](../src/graphs/context). [`geometryCache`](../src/bezeg/cache/GeometryCache.ts) now owns the revision used by mathematical objects to invalidate cached computations; graph adapters notify it when mutable external geometry changes. Cosmetic size changes redraw the board without invalidating mathematical values, and geometry implementations no longer depend on graph infrastructure.

[`PresetService`](../src/graphs/base/presets/Presets.ts) saves named presets under a `bezeg-2.0:` browser-storage namespace while retaining the established `preset-` keys inside the values and exported files. [`src/storage/appStorage.ts`](../src/storage/appStorage.ts) isolates these keys and the language preference from the original app sharing the `efodx.github.io` origin. Existing exported preset files remain explicitly importable through the validated file-import flow, and exports keep the same interchange keys. Presets can contain curve data, board bounds, and graph state. [`PresetSelector`](../src/graphs/base/PresetSelector.tsx) supplies saving, selection, deletion, text-file import/export, and batch image generation. Selected preset changes remount the app subtree through a React key; reset/import can remount a route subtree through `RefreshContext`.

This release uses a new public route base, `/bezeg-2.0/`. Browser-local presets from the original site remain under its original keys, so users who want them in this release must export a preset file from the original site and import it explicitly.

[`ClassMapper`](../src/graphs/curves/object/ClassMapper.ts) serializes curve types using string identifiers. Some identifiers retain the older `JSX` prefix even when the class is named `JXG`. Renaming them could affect saved files and browser presets.

There is no server or database implementation identified in the inspected application source. The owner confirmed that stateless means no backend, accounts, or server database, while browser-local presets and file exchange remain allowed. See [ADR 0001](adr/0001-static-client-only-app.md).

## Mathematical implementation and adapters

| Layer | Responsibilities and entry points |
| --- | --- |
| Point/curve APIs | Coordinate access, control-point mutation, evaluation and curve operations under [src/bezeg/api](../src/bezeg/api). |
| Mathematical objects | [Polynomial Bézier](../src/bezeg/impl/curve/polynomial-bezier-curve.ts), [rational Bézier](../src/bezeg/impl/curve/rational-bezier-curve.ts), [splines](../src/bezeg/impl/curve/bezier-spline.ts), and [PH](../src/bezeg/impl/curve/ph-bezier-curve.ts). |
| JSXGraph adapters | Wrap board points, provide X/Y evaluation callbacks, manage auxiliary polygons/constructions, selection, transforms, and DTO conversion in [curve objects](../src/graphs/curves/object). |
| Demonstrations | Defaults, parameter state, specialized constructions, and graph-level controls in [graph classes](../src/graphs/curves). |
| React controls | Sliders, counts, switches, modal dialogs, and command builders call mutable graph/curve methods. |

Polynomial evaluation uses recursive linear interpolation (De Casteljau). The same triangular scheme supplies displayed constructions, subdivision control points, and extrapolation. Degree elevation constructs a new polynomial representation. Rational evaluation uses weighted interpolation; subdivision/extrapolation operate on homogeneous coordinates and project back, while elevation blends weighted coordinates and weights. Geometry methods return new curves; adapters replace points or register resulting board curves.

Spline objects assemble polynomial pieces and derived control points for the specified continuity construction. Global evaluation selects a piece using normalized parameter spans and converts to that piece's local parameter. Spans are proportional to endpoint chord length raised to α. This differs from the fractional parameter transformation in the weighted polynomial/PH demonstrations.

PH geometry uses a start point and generating `w` points to derive a polynomial curve and rational offsets. Evaluation delegates to the underlying polynomial. PH speed/arc-length routines support uniform sampling; parameter inversion uses a predictor and four Newton corrections. Degenerate speed or rational denominators are not comprehensively guarded by this implementation. This inventory describes algorithms without certifying their numerical correctness over all inputs.

## Interaction and update flow

Point dragging advances `geometryCache`; callback-based JSXGraph curves also receive a coalesced full-board refresh so their separate X/Y callbacks observe the new geometry even when the board is already processing an update. Curve-wide gestures pass through board down/move/up handlers in `BaseCurveGraph` and adapter transform methods. Geometry setters invalidate freshness near the mathematical objects, while graph adapters still notify the cache for function-backed and externally mutable sources. Sliders and switches update React state, mutable geometry, board attributes, or combinations of these. Construction caches use both geometry revision and construction parameter where applicable. Separate X/Y callbacks can ask for the same curve evaluation twice; cached evaluations reduce repeated work within a revision.

Before replacing a curve scene, `BaseCurveGraph.importPresetData` disposes each curve's base JSXGraph objects, including control-polygon, convex-hull, and bounding-box auxiliaries, before removing shared graph points. This keeps stale auxiliary objects from corrupting JSXGraph's update state during guided-lesson transitions. Specialized curve constructions may still own additional objects and remain responsible for their own cleanup.

Graph-level and selected-curve commands remain distinct paths: `getGraphCommandsArea()` swaps to the selected-curve area. The shared workspace keeps editing, display, and save sections mounted when switched or hidden. Polynomial operation preview objects are initialized in an effect, with explicit preview buttons, rather than created while rendering command arrays. Numeric point forms resolve current points when applying coordinates, including PH points replaced by the hodograph editor. The uniform PH parameterization route adds its comparison controls to the workspace editor so they remain available alongside the PH tools.

Guided lesson scenes use the graph capability seam for renderer-owned visuals. The Bézier evaluation scene renders its reviewed worked example in the lesson panel and asks the curve adapter to mark the evaluated point at `t=1/2`; the marker is included in curve state so scene restoration removes it when the lesson advances or closes.

The PH editor initializes once per mount and adds a child board whose draggable `w` points are wrapped as geometry points. Disposal snapshots the current generating points, removes the parent-child relationship, disconnects its resize observer, and frees the auxiliary board. Workspace routes disconnect their main observer and free their main board on unmount. Legacy main-board disposal remains a separate engineering gap. Child cleanup uses the captured parent board rather than a parent component field that may already have been cleared.

## Preset contract and current failure modes

`PresetService` stores each demonstration's collection at `preset-<demonstration-id>` as `{ data: Preset[] }`. Each preset has `id` and optional `data`, `boardState`, and `graphState`. Board state stores the bounding box; curve graph data is an array of `[typeIdentifier, curveDto]` entries. DTO content is type-specific: polynomial points/state, rational weights, PH generating points, or spline construction settings. `ClassMapper` dispatches to static `fromDto` / `toDto` methods.

The selected name lives in `SiteContext`; changing it remounts the keyed app subtree. Loading restores bounds/state/data when present, otherwise the graph uses its default geometry and then calls `initialize()`. Some initializers regenerate objects or reset bounds, so restoration behavior must be checked per graph. Curve import explicitly clears selection.

Export scans the release's namespaced storage for keys beginning `preset-` and writes a single JSON object to `presets.txt`. [`PresetImport`](../src/graphs/base/presets/PresetImport.ts) validates recognized collections, DTO types, finite numeric data, graph bounds, required curve state, spline parameters, and PH degree before writes. The import dialog lists matching collections for replacement consent and keeps errors visible. Commit revalidates and attempts rollback on storage failure. Saving an existing name replaces geometry, board state, and graph state together. Preset interchange keys, DTO identifiers, and file shape remain unchanged; browser storage uses a release prefix, and arbitrary storage entries and malformed data formerly accepted by the unsafe importer are rejected. Shared axis/size/visibility singleton settings are still not comprehensively serialized.

## Export pipeline

[`FigureCapture`](../src/graphs/base/export/FigureCapture.ts) receives an explicit current container, SVG root and graph-session lifecycle. SVG still serializes the renderer tree; PNG still uses `html2canvas` on the board DOM. Both wait for graph work, fonts, current-container MathJax typesetting and images. Each wait is bounded, graph disposal cancels the operation, and late work cannot trigger a download. PNG hides only target-container assistive MathJax nodes and restores their exact display styles. Blob downloads revoke owned object URLs. SVG does not acquire HTML-rendered formula content outside its renderer tree.

[`PresetFigureBatch`](../src/graphs/base/export/PresetFigureBatch.ts) captures selected presets through a live graph owner and keeps PNG blobs local to one job before creating `slike.zip`. It awaits scene readiness instead of a fixed remount delay and restores the entry scene on success or failure while its session is alive. BaseGraph integrates scene disposal, reconstruction and transient runtime hooks; graph subclasses retain responsibility for extra constructions, PH child-editor state and selection. Overlapping batches on one owner are rejected; cancellable scene operations receive a signal to suppress stale callbacks. Capture does not change browser presets or the selected-preset context. Graph controls are temporarily unavailable during a batch. Running De Casteljau animation is restored paused at its entry parameter.

## Rendering investigation candidates

- [`AbstractJXGPointControlledCurve`](../src/graphs/curves/object/AbstractJXGPointControlledCurve.ts) gives JSXGraph separate X and Y callbacks, each calling `eval(t)`.
- [`PolynomialBezierCurve.eval`](../src/bezeg/impl/curve/polynomial-bezier-curve.ts) caches evaluated points by parameter and global revision. The first performance experiment adds point-only polynomial and rational interpolation on cache misses, avoiding copied intermediate rows and a duplicate result allocation. Full De Casteljau tables remain available for displayed constructions and other curve operations; global invalidation and sampling are unchanged. See the [performance spec](specs/bezier-drawing-performance.md) for scope and verification.
- Point dragging and several graph operations advance the shared cache revision. Broad invalidation may cause unrelated geometry to be recomputed.
- Board updates, mathematical evaluation, auxiliary constructions, and React remounting are separate potential costs. Measure them separately before choosing an optimization or replacing JSXGraph.

These are source-based hypotheses. No benchmark, browser profile, mathematical regression check, or runtime UX assessment has been performed during this discovery pass.
