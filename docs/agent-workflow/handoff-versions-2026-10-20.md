# Handoff versions and observed outcomes

Assessment date: 2026-10-20. Source contract: [evaluation follow-up](../specs/agent-workflow-evaluation.md#version-assessment-follow-up--2026-10-20). Current dispatch instructions: [agent workflow](../agent-workflow.md).

The records support clearer acceptance reporting and useful responses to specific instructions. They do not establish that successive templates reduced defects, elapsed time, or total effort. Later versions still needed substantive review and repairs. Retain the useful guidance, keep independent review, and make one targeted assertion-quality revision rather than expanding universal verification.

## Method and sample

Compared the introducing Git diffs with the [evaluation log](evaluation-log.md), through “Restore graph access during Guided lessons.” A read-only research worker independently enumerated version-labeled records; the handler checked the version changes and decision-bearing outcomes. Counts below are **task records**, not worker assignments or independent experiments. Follow-up phases and reused workers remain separate log records, so observations are correlated.

There are 32 explicitly versioned assignment-bearing records: v1 2, v2 1, v3 5, v4 8, v5 4, v6 12. Include “Apply historical workflow findings” under v2 because its research worker actually received v2, although its policy outcome introduced v3. Include handler-implemented work when it delegated a versioned smoke assignment. Exclude handler-only template announcements, acceptance corrections, synthetic fixture rows as separate tasks, and legacy records without a recoverable revision. Do not infer a brief version from its date: Batch B explicitly used v3 even though its record follows the v4 announcement.

Task difficulty, roles, staffing, model/effort, acceptance coverage, platforms, and tooling changed alongside the template. Full initial/revised briefs are not consistently retained; summaries establish reported instructions, not exhaustive compliance. Most records lack a comparable dispatch-to-acceptance duration and scoped usage. Later escaped defects are not systematically observed. Consequently there is no defensible version-level success percentage, speedup, token-saving estimate, or causal ranking.

## Closest comparisons and counterevidence

**Batch B (v3) versus Batch C (v4):** both delivered four analysis topics with independent release review. B's worker smoke rows were initially only syntax-checked; C's four graph/lesson workers ran their rows and all returned green. C still required one review round and one layout round, with seven layout collisions (five fixed and two partially fixed in that layout round). This supports actually exercising assigned rows, but the rows did not cover all visible acceptance. Different topics, changed effort/model settings, templates, an API interruption, and dependency recovery prevent a fair total-effort comparison. There is no measured layout improvement attributable to v4.

**Motion Phases 1–3 (all v6):** detailed invariants, diagnostics, five-frame review, and frame-preservation instructions produced green worker reports. Independent reviews in Phases 1 and 2 still found assertions against the wrong carrier or insufficient relationships: the derivative check did not establish a tangent through the point, accumulation checked an off-camera caption instead of the visible point, and null path data could satisfy presence/hash checks. A per-element check weakened an existing shared drag check. Phase 3 included handler premise probes and a correct stop on a board/brief contradiction, but also needed a camera correction. These are within-version feedback observations, not a v5/v6 experiment. They support a narrow wording improvement about what assertions prove.

**Environment diagnosis:** the Phase 1 handoff called a motion-smoke failure machine-specific/pre-existing. Phase 2 corrected that claim after CI failed: polling aliased with the loop, and the test was fixed. Preserve the correction when assessing the result. The existing stable-checkpoint/reproduction rule remains applicable; an unresolved failure is a coverage gap until its cause is established.

**Time and context:** recorded boundaries include v1 homepage work at 5m37s, v4 carousel at about four minutes, v5 color work at about nine minutes, and v6 restored clips at 17m19s. Their scope and timing boundaries differ, so ordering those durations says nothing about which brief is faster. v6 report caps have no comparable before/after reply length or context-occupancy measurements. Compaction and model pilots do not supply the missing comparison.

## Revision and follow-up

Adopt **v7**, changing only assertion guidance: identify the actual board object/rendered element and expected relationship, fail on missing/empty data, and preserve existing shared checks when adding a case-specific assertion. This addresses repeated Phase 1/2 review findings. Alternative explanations include implementation reasoning and incomplete source acceptance; wording alone may not fix them. Keep independent review and the current model, effort and task-size defaults. No universal extra screenshots, instrumentation, or new logging fields are added.

The effect of v7 is **unmeasured**. On a future comparable capture/geometry assignment, retain the decision-bearing wording and observe whether independent review finds wrong-object assertions, vacuous data checks, or weakened shared checks; include repairs and observable total effort through acceptance. Recurrence despite the explicit wording would count against its sufficiency. Absence would support adoption/compliance locally, without proving efficiency. If a prompt-only pilot is warranted, repeat an isolated/read-only equivalent task with stable settings, scope and review, changing only this wording and retaining exact briefs under the existing pilot contract.

Keep v2's acceptance mapping, v3's state/resource checks, v4's preview setup, v5's contradiction escalation, and v6's report caps provisionally. The records justify their practical purposes; they do not show that each addition paid for itself. Improve capture of already-required dispatch/acceptance boundaries during normal work before claiming an efficiency trend.
