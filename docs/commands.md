# Developer commands

Install [just](https://just.systems/) 1.30 or newer and the Node version declared by `package.json` (Node 24.15 or newer). On Windows, install just with `winget install Casey.Just`; with Rust on other platforms, use `cargo install just --locked`. Install project dependencies with `npm ci` before running these commands. Run `just --list` to see the available workflows and their descriptions.

## Agent skills

Bezeg's own skills (`smoke-tester`, `subagent-flow-evaluation`) come with this repository in `.agents/skills/` and need no installation. The owner's general skills live in the private [efodx/agent-skills](https://github.com/efodx/agent-skills) repository, so this step works only for the owner. On a new computer, run from Git Bash on Windows (or any shell elsewhere):

```sh
git clone https://github.com/efodx/agent-skills.git ~/IdeaProjects/agent-skills
~/IdeaProjects/agent-skills/install.sh
```

The installer copies each skill into `~/.claude/skills` and `~/.codex/skills`. To update later, `git pull` in that clone and rerun `install.sh`; edit skills there, not in the installed copies, and see its README for `install.sh diff` and per-tool options.

`just check` runs TypeScript, ESLint, the full Vitest suite once, then a production build. `just unit [args...]` forwards each argument to `npm test -- --run`; for example, `just unit src/learning/content/lessonMathNotation.test.ts -t "scans every lesson|lesson prose wraps"`. `just check-localization` runs TypeScript and a production build. `just build` runs the existing production build and records local provenance for the resulting `build/` directory.

`just smoke [args...]` builds and runs the existing Playwright smoke script. `just smoke-built [args...]` runs that script against an already built app after checking that its source inputs and output still match the last successful runner build. Smoke options are forwarded as individual arguments, including quoted filters such as `just smoke-built tests/home.smoke.spec.cjs --grep "homepage owns|homepage fits"`. Use `--port 4300` to choose the server port; the helper removes that option before forwarding the remaining Playwright arguments. Without it, `SMOKE_PORT` is inherited, or port 4173 is used. Playwright starts and disposes its own server, so a separate preview is unnecessary. An occupied port fails.

`just smoke-lesson <id>... [args...]` runs the guided-lesson smoke rows for the given lesson ids (the `id:` rows of `tests/guided-lessons.smoke.spec.cjs`) against the existing build, like `smoke-built`; for example, `just smoke-lesson taylor darboux --port 4391 --workers=1`. Unknown ids fail with the list of known ids. Arguments after the first option are forwarded to Playwright.

`just typecheck` runs only TypeScript with the local compiler. `just lint [args...]` runs the local ESLint on the whole repository, or on the given paths and options. It covers `src/`, the Playwright specs and helpers in `tests/`, and the Node tooling in `scripts/` and `tools/`; TypeScript checks only `src/`, so lint is the only static check for `.cjs` files (for example, an undefined variable in a smoke row). Violations that predate a rule are recorded in `eslint-suppressions.json`. Fix new violations rather than suppress them. After fixing a recorded one, run `npx eslint . --prune-suppressions`, because ESLint fails while the file lists suppressions that no longer occur. `just loc <pattern>` prints the localization keys whose key, Slovenian text, or English text matches a case-insensitive regex, with both translations and a `(missing)` marker when one catalog lacks the key; it shows at most 40 keys. `just ci [sha]` lists recent workflow runs on `master`, or for one commit, through `gh`; when a listed run failed, it adds a short excerpt of the failing test lines from `gh run view --log-failed`. It is read-only and needs an authenticated `gh`.

`just preview [port]` runs the existing production preview server in the foreground after the same provenance check. Its startup message gives the URL, revision, dirty state, and log path; confirm reachability before browser handoff. Stop it with Ctrl+C (exit 130 records interruption). `just tooling-test` runs the focused Node tests for the command runner. `just eval <list|setup|grade|calibrate>` drives the [workflow evaluation harness](../tools/agent-eval/README.md).

Each workflow writes its complete output to a unique file under `.command-logs/`, which is ignored by Git. Successful runs print a compact status and log path. Failures print a bounded excerpt and preserve the child exit code. Set `BEZEG_VERBOSE=1` to stream full child output while keeping the log. Runner provenance fingerprints `src/`, `public/`, build configuration files, `.nvmrc`, present Vite environment files, and `NODE_ENV`/`VITE_*` values. It is local and is not created by direct `npm run build`; use `just build` before `just smoke-built` or `just preview`.

All runner commands run at below-normal priority, so a game or the desktop keeps the CPU. Heavy commands (`check`, `build`, `smoke`, `smoke-built`, `smoke-lesson`, and `unit` without a file path) share machine-wide test slots across every checkout and worktree. A run waits and names the busy holders when all slots are taken. The summary line shows the slot and worker count. `scripts/test-slots.cjs` sizes slots and Vitest/Playwright workers per slot from this computer's threads and memory, after reserving 9 GB for the desktop and the agent sessions (16 GB, 12 threads: 1 slot of 4 workers). `unit` runs filtered to a path skip the queue with at most 2 workers. Every heavy command, and also `typecheck` and `lint`, then passes a memory gate: it waits until starting leaves at least 2 GB of memory available, and starts are spaced a minute apart machine-wide so each reading includes the previous run's growth. `unit`, `check` and smoke runs then use only the workers that fit at 1.5 GB each. Below that floor Windows signals critical memory pressure, and Claude Code stops the background commands of sessions idle for 30 minutes. After 20 minutes of waiting a run starts anyway with a warning. `BEZEG_MEMORY_FLOOR_GB` changes the floor; `0` turns the gate off. A heavy command that is already running in the same checkout is refused with the running pid: wait for that run and read its log in `.command-logs/` instead of starting it again. Override per machine with the user environment variables `BEZEG_TEST_SLOTS`, `BEZEG_TEST_WORKERS` (per slot), and `BEZEG_TEST_PRIORITY` (`idle`, `below-normal`, or `normal`). Explicit `--maxWorkers`/`--workers` arguments still win. Direct `npm test`/`npx vitest` outside CI skips the queue but is capped at one slot's worker share; CI keeps Vitest's default.

For Codex handler context, run `node tools/agent-usage/codex_worker_watch.cjs --self --once` at task start and bounded work boundaries; follow the [self-check and handoff procedure](../tools/agent-usage/README.md#codex-handler-self-checks). For worker budgets, run `node tools/agent-usage/codex_worker_watch.cjs --agent-path <canonical-worker-path>` after dispatch. Its threshold event requires a handler-delivered handoff; follow the [monitor and relay procedure](../tools/agent-usage/README.md#codex-monitor-then-relay), including terminal-event exit codes and cleanup. Test the watcher with `node --test tools/agent-usage/codex_worker_watch.test.cjs`; Developer tools CI runs that suite on Windows and Linux.

The offline preview generator supports `PREVIEW_RECAPTURE_IDS` (comma-separated demonstration IDs) to regenerate selected posters and their clips while retaining the other assets and source-frame evidence. By default it requires the same mathematical-source fingerprint and always validates retained output checksums. For an intentional selective refresh across source revisions, `PREVIEW_RECAPTURE_PRESERVE_SOURCE_PROVENANCE=1` preserves the retained media’s previous source revision/fingerprint and prior selective-recapture chain, and marks the manifest as mixed-source. Review the retained evidence before using this flag; it does not certify retained media against the current runtime. If a reviewed capture-tool change alters the presentation fingerprint, `PREVIEW_RECAPTURE_VERIFIED_PRESENTATION=1` explicitly asserts that shared presentation and retained recipes/motions remain unchanged; inspect that diff before setting it. The manifest records previous fingerprints/revisions and the retained asset groups. This is an operator verification flag, not an automatic compatibility check.

The capture manifest (`scripts/demonstration-previews/manifest.json`) is tooling evidence, so it lives outside `src` and is not bundled; its FFmpeg provenance records repo-relative names, never absolute paths. `src/demonstrationPreviewAssets.ts` is `Partial<Record<DemonstrationId, string>>`: a new Demonstration does not block typecheck, but `src/demonstrationPreviewAssets.test.ts` fails naming the missing ids until `node scripts/capture-demonstration-previews.cjs` regenerates the posters (the catalog card renders an empty frame without a poster).

The preview generator also captures surface demonstrations (currently `patch-tensor`, `patch-decasteljau`, `patch-derivatives`, `patch-subdivision`, `patch-joins` and `patch-triangular`) by reading the framing the surface view mirrors to its host as `data-surface-framing`; its validator rejects blank frames, a camera that differs from the recipe, and projected control points outside the frame. It checks the SVG surface view (`scripts/surface-view-evidence.cjs`), not a canvas; surface clips have the app's cream background. The 2026-10-30 recapture of all six surface demonstrations used FFmpeg 7.0.2. Selective recapture with `PREVIEW_RECAPTURE_IDS=patch-tensor` across source revisions needs `PREVIEW_RECAPTURE_PRESERVE_SOURCE_PROVENANCE=1` and, when the presentation fingerprint changed, `PREVIEW_RECAPTURE_VERIFIED_PRESENTATION=1`; the manifest then records `selectiveRecapture.mixedGraphSource: true`. A full generation (`node scripts/capture-demonstration-previews.cjs` without `PREVIEW_RECAPTURE_IDS`, against a running `just preview 3012`, the script's default `PREVIEW_BASE_URL` port; set `PREVIEW_BASE_URL` for another port) writes no `selectiveRecapture` block, so it clears the flag.

Measure the Bézier drawing playground drag (spec criterion 5) with `node scripts/playground-perf.cjs` against a running `just preview 4312` (`PREVIEW_BASE_URL` overrides the base; `PERF_RUNS`, `PERF_CASE=1,2`, `PERF_DRAG_MS` tune it). It seeds a 20-anchor closed drawing, samples requestAnimationFrame intervals during a scripted handle drag in four cases, and exits non-zero if the seed does not load or fewer than 60 frames are sampled; results go in [the performance results](bezier-performance-results.md#drawing-playground-drag--2026-10-31).

Refresh the six Bézier reader activity figures with `node scripts/capture-chapter-figures.cjs`. Build with `just build`, start its production preview with `just preview 4387`, then run the capture command in another terminal and keep the preview running. `PREVIEW_BASE_URL` can point the script at another reachable production preview base. It opens each exact chapter activity query in a fresh browser context and writes board-only PNGs plus a provenance and scene-check manifest under `src/images/learning/bezier/`; it does not change catalog captures or graph scenes. Captured graph labels remain in Slovenian because the graph itself has no English label mode; each reader figure supplies Slovenian and English alternative text and captions.

After the guided-example registry is stable, generate its complete JSON inventory with `node scripts/generate-guided-example-inventory.cjs` (default: `docs/reviews/illustrated-chapter-examples/capture-inventory.json`) and capture it with `node scripts/capture-guided-example-previews.cjs path/to/guided-example-inventory.json`. Each entry has `id`, `demonstrationId`, the full canonical `path` beginning `/bezeg-2.0/` with exactly one `?example=` query whose final identity segment matches the demonstration ID, and a SHA-256 `sceneFingerprint` of the prepared scene and actions; optional `actions` describe that authored preparation and optional `expected` checks specify visible JSXGraph `types`, `curveCount`, `points`, and sampled `curves`. The runner opens that URL in a clean context and never applies controls or actions, verifies the first guided-example frame is current and settled, requires substantive visible graph geometry with finite curve samples, confirms the served production bundles match the local build, and writes board-only PNGs plus `manifest.json` under `src/images/learning/examples/`. The manifest binds IDs, demonstration IDs and URLs to scene fingerprints, board evidence, build/source provenance, deterministic viewport/frame settings, and each image checksum. Every entry also carries a `recipe`: `{kind: 'start'}` captures the first frame, and a highlight recipe, authored in `src/learning/chapter/guidedExampleHighlights.ts` (`guidedExampleHighlightRecipes`, keyed by example id), captures a later state instead. A highlight recipe names a lesson frame id (the generator resolves it to a position and fails on an unknown id), an ordered `steps` list, `expectChange`, and independently computed `checks` (`types`, `curveCount`, `points`, `curves`, see `guidedExampleHighlightExpectations.ts`). The runner reaches the frame with the lesson's own previous/next buttons, then applies the steps as a learner would: `goto-frame` (navigation), `frame-action` (presses the frame's action button), `explore` (presses the lesson's "Skrij" or "Opazuj na grafu" button so the inspector unlocks), `select-tab` (`edit`, `display` or `save`) and `set-control` (`checkbox`, `slider` or `number`, found by its Slovenian accessible name in the open tab). Validation rejects an unknown frame or step kind, a `select-tab`/`set-control` step without an earlier `explore`, a lesson-panel step after `explore`, a bad tab, control kind or value, an unreachable frame, a missing or ambiguous control, a slider or number value outside its range or step, an empty board, an unchanged board when `expectChange` is true, failed geometry checks, and a retained image whose recipe changed since capture. Capture all entries whenever inventory, scene, presentation, or build fingerprints change; a run without `--id` is a full run and rewrites the manifest, even for a single-entry inventory. To recapture a subset, pass one or more `--id <id>` options (or `PREVIEW_EXAMPLE_IDS`); partial runs require a complete, current prior manifest and reject stale mappings, missing or edited retained images, or changed presentation or build fingerprints. Recipe, scene and inventory-entry changes are tolerated only for the selected ids (they are recaptured, then validated with the full published set); a changed retained entry fails, and a manifest without per-entry fingerprints needs one full run first. Chapter batches should provide their final complete inventory after content consolidation; this command is tooling only and does not synthesize scenes.

Board-based chapter-owned lessons (the Linear maps chapter; the Geometry stream's convexity chapter will reuse this) use a chapter mode: `node scripts/generate-guided-example-inventory.cjs --chapter <chapterId> [out.json]` (default `docs/reviews/<chapterId>/guided-example-inventory.json`) builds `{kind: 'start'}` entries from the chapter's registry with authored `expected` checks (an empty expectation fails), and `node scripts/capture-guided-example-previews.cjs <inventory> --family <chapterId>` writes board-only PNGs and `manifest.json` under `src/images/learning/examples/<chapterId>/`. The retained manifest rejects chapter-owned entries, and a chapter destination accepts only its own ids and route. A new chapter adds one entry to `chapterInventories` in the generator and `chapterFamilies` in the capture script, and its copy to `CHAPTER_GUIDED_EXAMPLE_PREVIEWS` in `src/learning/chapter/guidedExamplePreviews.ts`.

Surface guided-example inventory entries additionally require `expected.surface` with independently authored camera and exact rendered-owner identities/kinds, each with three finite xyz samples in producer order. The runner reads `data-rendered-surface-owners`, which the view publishes from the mesh it drew, validates the first frame and resized capture, and preserves observed samples in the manifest. It rejects cropped projected controls/visible label boxes and requires full indexed-mesh bounds within the frame, including point-free teapot and subdivision views. The conservative projected mesh box is cached across orbit and retained for prepared-frame and captured-frame revalidation. The producer and runner do not create authored examples or establish capture success; see [the surface evidence contract](reviews/bezier-patches/t13-surface-evidence.md).

Preview generation also requires FFmpeg and FFprobe; set `PREVIEW_FFMPEG` and `PREVIEW_FFPROBE` to explicit executable paths when they are not on PATH. The concept-led media was verified with FFmpeg 6.1.1. The encoder validates RGB color metadata and every decoded background frame, and rejects incompatible tool output. Number actions may declare `displayDecimals` when a field formats its blurred draft; their mathematical checks must still verify the full-precision board coordinate independently.

In PowerShell, enable streaming with `$env:BEZEG_VERBOSE='1'` and remove it afterward with `Remove-Item Env:BEZEG_VERBOSE`. On Unix, use `BEZEG_VERBOSE=1 just check`. Read logs when a summary flags warnings. Logs are retained locally until you remove them. The separate Developer tools CI workflow checks the runner on Windows and Linux when tooling/dependency files change; the existing Browser smoke deployment gate continues to use npm directly. Choose verification for the affected behavior: `just check` does not include browser checks.
