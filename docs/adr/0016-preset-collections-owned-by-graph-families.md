# Each Demonstration's Preset collection is a static definition in its graph family's module

Accepted on 2026-10-21 with [graph contract deepening task 02](0016-preset-collections-owned-by-graph-families.md). The file importer used to hold every collection's rules in central lists: accepted keys, function-model parsers, their diagnoses, curve types, a spline-type table and a key-prefix rule. Each graph separately declared the same key in `presets()` and parsed its own data on import. The file importer and the function graphs parsed the same data, but the diagnoses were derived separately, next to the parsers, and curve graphs did not check stored data at all.

A Preset collection definition is a frozen object with a `key` (stored as `preset-<key>`) and `check(data)`. `check(data)` returns either the data to import or the localized reason for the rejection. It needs no graph or board. Definitions are grouped by graph family and keyed by Demonstration id. `functionPresetCollections` (in `src/graphs/functions/`) pairs each model parser with its diagnosis. `curvePresetCollections` (in `src/graphs/curves/`) builds every collection from shared per-curve-type DTO rules plus the expected curve type, the PH degree, or permission to hold no curves (Bernstein). A graph returns its definition from `presetCollection()`, and `presets()` reads the key from that definition. The file importer lists the two family modules and the documented legacy collection `g1-spline`. It keeps only the file envelope, names, bounds, the shared scene-state rule, conflict reporting and the atomic write with rollback. When a graph loads stored data (a Preset, a figure-batch Preset), `BaseGraph.storedPresetData` applies the same `check`. Data that is missing or rejected loads the default scene with a console warning. `importPresetData` takes typed family data: curve entries `[CurveTypeName, CurveDto][]` or the function model `M`.

We considered three alternatives. Static members on each graph class were rejected because the file importer would have to import every graph module, and graph modules already reach the importer through `BaseGraph`. That import cycle would reach module-level constants. A `graphFactories`-derived registry was rejected because it constructs graphs, so preflight could not run without them. A generic rule framework (a descriptor per field with range, type and message) was rejected because the deletion test fails: the rules vary in kind (a model parser, curve DTO shapes, PH degree), and a framework would move each rule into a shallow entry without concentrating it. The scene-state rule keyed on field names stays one shared function. Its field names mean the same thing in every collection, and splitting it per family would only duplicate or loosen it.

Locality is per family. The analysis modules exclude localization, so diagnoses cannot sit beside their parsers. Adding a function Demonstration touches its `*Model` parser, one entry (and optional diagnosis) in `functionPresetCollections.ts`, and its graph's `presetCollection()`. A curve Demonstration needs one entry in `curvePresetCollections.ts` and its graph's override. The file importer is touched in neither case. A check must never reject data that the graph loads correctly. The curve rules therefore require only the curve-state parameters an adapter applies unconditionally; display switches may be missing and read as off. Rational weights are only required to be finite, because the weight controls do not clamp them.

Collection keys, DTO names and stored formats are unchanged; `src/graphs/base/presets/PresetCatalog.test.tsx` pins the key list. Four behaviors changed. The file importer now accepts curve states without display switches (rational states also without `decasteljauT`), so it accepts everything a stored Preset could hold. Exported G1 and symmetric G1 spline files now import: their curve state's `b` array was rejected before. A G1 file whose `b` is not one positive number per junction gets a new localized diagnosis. A stored curve Preset whose data its collection rejects now loads the default scene instead of failing to load. Function Presets with string data, which the app never wrote and the file importer always rejected, are now rejected by the graph as well.
