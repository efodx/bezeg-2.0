# Graphs declare transient state once; the base graph applies it on every scene replacement

Accepted on 2026-10-21 with [graph contract deepening task 01](../tasks/graph-contract-deepening/01-graph-transient-state.md). Transient state is graph state outside Preset data and the scene store that changes what is drawn or what controls show, such as the selected curve, a rational curve's standard form and effective weights, the Elevation overlay or the PH hodograph view. Graphs had answered "what is my transient state?" separately for each hook family: scene-field resets, figure runtime state, lesson checkpoints, the lesson default scene and figure scene state. The families drifted apart. Values were saved twice with different validation, some were saved in no checkpoint at all, and after a restore some redraws ran only on some paths.

Each graph now overrides one pair, `captureTransientState()` and `restoreTransientState(saved | undefined)`. An undefined value means the transient state of a freshly loaded scene. Each graph also declares one idempotent `syncReplacedScene()` for drawing that a Preset import does not rebuild, and may override `sceneGraphState()` for the scene state a Preset or checkpoint saves. `BaseGraph` owns every replacement path (mount, Preset load, reset and import, figure batch Presets and entry restore, lesson checkpoints, the lesson default scene) and applies them in a fixed order: Preset data, scene state, transient state, scene sync. Lesson checkpoint capture and restore are private to the base graph. Lesson restores and the default scene replace the scene state instead of merging it, and they redraw synchronously, so a rollback within one tick is drawn before the host commits. State that follows from Preset data is derived rather than declared: the repeated-subdivision step count is computed from the number of pieces.

We considered a per-field descriptor, in which each graph lists fields with read, write, default and validation functions and the base clones, validates and resets them generically. The fields are not independent, though. Rational weights must be set with the Farin sliders rebuilt around them, the selection must follow the import, and the overlay's remembered polygon visibility derives from the imported curve. Descriptor entries would therefore restate ordering in closures, and the base would grow a generic validation layer, a serialization framework of shallow per-field modules. We also considered running the figure path's full board teardown and `initialize()` for lesson restores. That would make `initialize()` the single redraw, but every lesson Back step would rebuild the whole board and reset function-graph views. `initialize()` is also not idempotent across paths (it leaked the De Casteljau whole-curve plot).

The in-memory lesson checkpoint value renames `runtimeState` to `transientState` and drops the graph-specific `farin` and `stepsDone` keys. Checkpoints are never stored, so no stored data, route or Preset format changes. Learners see three changes. Each Preset in a figure batch is captured with fresh transient state, as loading it would show it. Lesson Back, rollback and the default scene rebuild scene-backed controls. A scene saved during De Casteljau playback is restored paused. Transient state never reaches Presets, URLs or progress. ADRs 0002, 0006, 0012 and 0013 are unchanged.
