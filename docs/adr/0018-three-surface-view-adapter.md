# Three.js behind the surface-view adapter

Status: accepted, 2026-10-26. Source: [Bézier patches P2](../specs/bezier-patches.md#acceptance-criteria). Choose Three.js for the patch family, lazy-loaded behind the surface-view adapter. Keep JSXGraph1.14.1 for existing curve graphs and the independently owned parameter-domain board. This is a family-specific addition; it does not migrate the app shell or curve renderer.

The [completed measurement populations](../reviews/bezier-patches/renderer-measurements.md), [JSX confirmation](../reviews/bezier-patches/jsx-final.md), and [Three depth/export evidence](../reviews/bezier-patches/three-export-depth.md) support the choice. JSXGraph's corrected mesh and actual32-patch teapot work, and batching substantially improves its construction rebuild. Nevertheless, its prototype retains PNG taint, touch-z XY drift, listener accumulation and unaccepted four-view depth ordering. Three has verified actual-owner pointer editing, combined touch XY/z, export/depth and mount disposal, with usable default-density interaction proxies. These findings justify choosing the isolated fallback without claiming a renderer speed ratio or fundamental JSXGraph incapability.

## Surface-view interface and ownership

`attach(host)` creates one owned view; `reconcile(scene)` renders plain scene data; `onEdit` delivers typed point, parameter and camera edit intents; `dispose()` cancels pending attachment work and releases all resources idempotently. A subscription returns its unsubscribe function. The scene carries stable identities and geometry revisions, finite xyz coordinates, camera, layers and evaluated constructions. It contains no React, Three or JSXGraph objects. The model/scene store remains authoritative: reconcile does not emit edits, and accepted intents update the scene synchronously before the next action reads it. Renderer-private caches never become graph-field state mirrors.

The adapter hides camera projection, picking, depth, text placement, resize and GPU ownership. Geometry independently supplies sampled meshes and exact constructions. Tensor meshes use the rectangular parameter grid; triangular meshes use the canonical barycentric lattice and explicit triangle faces, with three independent iso families. A degenerate reparameterized rectangular surface is rejected as the triangular teaching path. The adapter owns its renderer, canvas, observer, listeners, animation frame, geometries, materials and label assets. The hosting graph/session owns adapter attachment and the separate parameter board, plus Presets, commands, export and Presentation mode. Disposal and async cancellation must be checked through that interface.

Pointer drag intersects a fixed horizontal plane through the starting point. Shift or the visible z-mode toggle instead changes only starting z from vertical screen displacement; starting x/y and camera stay exact. Pointerdown selects the nearest visible owned point, with the selection retained through pointerup/cancel. The structured x/y/z editor and index selection provide access when perspective or occlusion prevents direct picking. Responsive camera fitting must expose the default net at narrow widths; the spike's offscreen point0 is a recorded production requirement, not a supported default layout.

## Defaults, budgets and capstone

The initial prototype target was8 iso intervals and8 shaded subdivisions per patch edge, with16 available explicitly. Production reconciliation (2026-10-29): tasks07–10 delivered8 iso intervals and16 shaded subdivisions for ordinary patches; retain that smoother shaded mesh rather than change previously delivered scenes and Presets. The [integrated measurements](../reviews/bezier-patches/t14-performance-h26.md) exercise those actual defaults and16/16 on desktop1440×1000 and narrow390×844 with constructions shown. The alternative8-shading option remains available but was not separately timed in that run. This is a documentation reconciliation of existing behavior, not a new route or data change.

At the default density, require drag pointer-event-to-next-rAF p95≤60ms and orbit p95≤16.7ms on the recorded comparison host; the Three prototype's observed worst default values are46.7ms and4.1ms. Also require active drag/orbit frame duration p95≤50ms, excluding idle/host evidence-write intervals, and settled exact geometry after every gesture. The active-frame budget is a production acceptance target, not a pass inferred from the contaminated continuous rAF series. Record actual input-to-visible update evidence separately; do not relabel next-rAF timings as presentation latency. If integration misses these budgets, profile the responsible layer before changing defaults or renderer.

The32-patch teapot is feasible as a `patch-joins` Preset/lesson capstone at tiling8 (4096 triangles). It has no single-patch parameter inset or editable single net. Tiling16 (16384 triangles) stays optional and needs integrated stress acceptance. Preserve the reviewed data attribution/license beside the asset. Both renderers were measured at both tilings and viewports; repeating iso settings does not add teapot iso curves.

## Export and remaining implementation acceptance

SVG contains a current raster image of the depth-correct WebGL geometry and vector label content. PNG uses the same current scene and visible labels. This preserves appearance but does not provide editable vector surface paths; that is the accepted export tradeoff. Pure-vector reimplementation is rejected because it duplicates depth/rendering and previously misordered lines. Production labels must use the existing MathJax pipeline; prototype plain text does not fulfill that requirement.

Production tasks must still deliver keyboard u/v sliders (read-only clamped w), numeric xyz, index selection, responsive fitting, bilingual controls, Preset validation/camera restoration, synchronous lesson actions and full lifecycle/export/accessibility checks. Ordinary DOM parameter sliders are UI work and do not require another renderer trial. Later tasks retain all P5–P10 requirements; this decision accepts the investigated renderer and budgets, not completed production integration. There is no route or stored-data break in this decision. A whole-app Three migration and a new backend remain outside scope.

The optional standalone `patch-compare` route is omitted in favor of a comparison view within `patch-triangular`, showing the two domains at matching boundary degree. Existing routes are unaffected; chapter links target that authored comparison scene.
