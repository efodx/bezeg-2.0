## Standards and runtime findings

### R1 — P2: an open Preset form bypasses a subsequently activated lesson lock

Open Save current state, enter the name of an existing Preset, start the Bézier guided lesson from the header, hide its card, then press Enter in the still-open form. The existing Preset is overwritten with the lesson's curve. Opening Delete confirmation before entering the lesson also permits deletion after the card is hidden. The surrounding menu correctly displays its locked state.

[PresetSelector.tsx](../../src/graphs/base/PresetSelector.tsx), lines 128–131 and 105, calls mutation handlers without checking the current unavailability reason. The opener is guarded, but the previously opened form is not. The real graph/lesson/storage reproduction failed both expected-preservation assertions. The existing contract at [PresetSelector.test.tsx](../../src/graphs/base/PresetSelector.test.tsx):170 requires state-changing controls to be unavailable during a lesson. Introduced in `3b169fb3`.

Repair every commit route, including keyboard submission and rename, against the current lock. Put the authoritative check at the command entry as well as displaying the reason in the controls.

### R2 — P2: relocated playback remains keyboard-operable under a lesson card

At a viewport up to 700 px wide or 500 px high, the playback group moves out of the inspector into [DemonstrationWorkspace.tsx](../../src/graphs/base/DemonstrationWorkspace.tsx):254. Only the inspector is made inert at lines 182–185. [GuidedLessonLayout.css](../../src/learning/runtime/GuidedLessonLayout.css):30 blocks pointer events on the relocated group, but keyboard activation remains available.

In the real Bisection host with the first instructional card open, Enter on Next step changed the graph model from step 0 to step 1 without changing the instructions. The expected-preservation assertion failed. This violates [lesson-navigation-stability.md](../specs/lesson-navigation-stability.md):43. Introduced in `e2f5dd7c`. Apply the lesson interaction lock to the relocated playback group and test Tab/Enter across the breakpoint.

### R3 — P2: a documentation push can conceal an unverified runtime push

A runtime push cancelled during the scope job has not run checks/unit. [ci-change-scope.cjs](../../scripts/ci-change-scope.cjs):187–199 skips it, and lines 229–241 accept an older successful run without comparing that run's source tree to the current tree. A subsequent documentation-only push therefore reports `fullVerification: false`. The same race exists while the previous run is still in progress, because the API query asks only for completed runs.

The [workflow](../../.github/workflows/browser-smoke.yml):28–30 permits scope cancellation; line 222 marks the skipped-check run successful, and line 228 skips deployment. A deterministic probe using the actual final docs-only commit range and simulated Actions history reproduced the incorrect scope decision. No live deployment incident is asserted. Daily verification may eventually check the code, but does not deploy it.

The guard originated in `966ba9d3`. The verification policy intends cancelled code to remain covered ([verification-throughput.md](../specs/verification-throughput.md):234). Decide documentation-only eligibility from changes since a verified source revision, rather than merely inheriting a prior run's green verdict. Verification and deployment provenance must remain distinguishable.

## Specification and mathematical findings

### M1 — P2: Secant reports nonconvergence at an exact root

On Root finding, select Secant, `x³ − x`, starts 0 and 2, then advance once. The next intercept is exactly `2 − 6 × (2 − 0) / (6 − 0) = 0`, with residual zero. [rootFinding.ts](../../src/analysis/rootFinding.ts):175–178 instead returns `repeated-iterate` before evaluating that new residual. The graph consequently announces nonconvergence.

The accepted model and history probe produced `[0, 2, 0]` with zero residual and failed the expected `root-found` assertion. [numerical-methods-lessons.md](../specs/numerical-methods-lessons.md):144,153 distinguishes exact-root and cycling termination. Introduced in `c52e801e`. Test the newly reached root before classifying recurrence.

### M2 — P2: a removable hole is listed as a zero

In Rational functions, choose the Hole example and increase the numerator's multiplicity at 1 to two. The result `(x + 1)(x − 1)² / (x − 1)` is undefined at 1; its only zero is −1. [rationalFunctionModel.ts](../../src/analysis/rationalFunctionModel.ts):218 lists both −1 and 1, despite having constructed the excluded set at line 213. [RationalFunctionGraph.tsx](../../src/graphs/functions/RationalFunctionGraph.tsx):520 displays that incorrect list beside the hole.

The valid public model-edit reproduction failed the expected-zero-list assertion. [school-function-graphs-lessons.md](../specs/school-function-graphs-lessons.md):54,104 requires undefined values at holes and distinguishes zeros, poles and holes. Introduced in `ed2d95b0`. Filter numerator zeros through the original domain; algebraic cancellation must not enlarge it.

### M3 — P2: a valid interior knot crashes the B-spline basis board

Change the default quadratic's interior knot from 1 to `0.0000000001`, producing `[0,0,0,1e-10,2,2,2]`. Graph editing and Preset validation accept it. [bsplineBasisModel.ts](../../src/graphs/curves/bspline/bsplineBasisModel.ts):155 subtracts a fixed domain-relative `2e-9` to sample the left limit, yielding `-1.9e-9` outside `[0,2]`. The live board update throws a `RangeError`.

The reproduction exercised the parser, pure sampler and actual GraphHost edit. [b-splines-nurbs-lessons.md](../specs/b-splines-nurbs-lessons.md):39 and L1 allow these nondecreasing raw knots. Introduced in `27a58bcf`. Bound a left sample by the preceding distinct knot, including adjacent representable values; a fixed epsilon is not a valid one-sided evaluation rule.

### M4 — P2: a valid reparameterized NURBS circle loses its accuracy readout

Keep the supplied unit circle's points and weights and import knots `[-0.1,-0.1,-0.1,-0.025,-0.025,0.05,0.05,0.125,0.125,0.2,0.2,0.2]`. This is the same circle on an affine parameter domain. [bsplineNurbsModel.ts](../../src/graphs/curves/bspline/bsplineNurbsModel.ts):59 computes its final sample as `0.20000000000000004`. The kernel refuses the out-of-domain value; [BSplineNurbsGraph.tsx](../../src/graphs/curves/bspline/BSplineNurbsGraph.tsx):188 converts the exception into a NaN radial-error readout.

The actual graph import and readout reproduced this. Expected radial deviation remains below `1e-12`. The requirement is [b-splines-nurbs-lessons.md](../specs/b-splines-nurbs-lessons.md):91/L5. Introduced in `2d2da56c`. Use the exact stored endpoint for the last sample, as the basis sampler already does for its uniform grid.

### M5 — P2: Monte Carlo Replay presents nonexistent results as zero

Select Monte Carlo area in Simulation and press Replay. [SimulationGraph.tsx](../../src/graphs/random/SimulationGraph.tsx):685 resets the displayed sample count to zero; lines 894,899–900 substitute zero for the π estimate, its error and its standard error. The graph correctly hides its estimate marker, while the inspector reports three numerical zeros.

The actual host/control/readout probe reproduced all three zeros. With no observations, those values are unavailable, not zero. [randomness-simulation-lessons.md](../specs/randomness-simulation-lessons.md):81–82 defines the estimate and uncertainty using the sample count in their denominators. Introduced in `2b41f442`. Render an explicit no-samples state until the first observation.

Start by repairing the two existing consumers; only extract behavior actually shared by them. Do not widen the mathematical kernel's accepted domain to hide invalid renderer samples.
