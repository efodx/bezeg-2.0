# Parity by golden values (task 02, slice 4)

To record a graph, add a `Sample` to `SAMPLES` in `src/graphs/base/declare/parity.test.tsx` (a demonstration id, a file under `src/graphs/<family>/__parity__/`, and five to eight states, each a list of `graph.parameters.write(key, value, 'learner')` writes or a custom `apply`, chosen so every shown value changes at least once), then run `BEZEG_PARITY_RECORD=1 just unit src/graphs/base/declare/parity.test.tsx`; the test mounts the real graph, records the Slovenian text of the panel's `data-readout` rows (key: label plus order), `data-readout-note` sentences, `<output>` read-offs and the board's text captions after each state, checks that two recordings are identical and that every state differs from the previous one, and writes the JSON. To check a declared graph, run `BEZEG_PARITY_CHECK=1 just unit src/graphs/base/declare/parity.test.tsx` (add `BEZEG_PARITY_REPORT=1` to write `<recording>.report.txt` beside each recording): `checkParity(recording, declarations)` renders `getDeclaration()` after each state to text (`name symbol value unit`, notes, formula), matches rows by name, symbol or id, compares values after normalising whitespace and the minus sign, and reports `missing`, `extra` and `different` entries with the state index; a recorded row that is a sentence may be matched by a declared note, and board captions no declared text contains are listed as information only (`uncoveredCaptions`). Recordings are deleted in task 10.

What the recorder cannot see: values drawn only on a canvas, MathJax output (a formula is compared as the panel's text content or declared TeX source, not as rendered), live regions (`data-readout-live` is left out because it lags and mutes while playing), and sliders' and inputs' own values (the declared `parameters` are not compared).
