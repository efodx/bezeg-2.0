# Audit 2: board interaction (drag, snap, keyboard nudge, view after edit)

Scope: src/graphs board interaction. C1-C15 excluded per the spec catalogue.
Row format: pattern | file:line evidence | what differs for a user | suggested shared control.

## Findings (appended as checked)

PARTIAL (budget handoff). Rows checked so far:

1. Arrow-key step per selected point differs | PointSetGraph.tsx:520-531 (one grid step, no Shift); CrossRatioGraph.tsx:231-238 (one unit, no Shift); FivePointGraph.tsx:325-334 (1/5 step, Shift = one unit); PolePolarGraph.tsx:287-295 (0.2 step, Shift = one unit, ideal P turns direction); PascalGraph.tsx:305-312 (conic position, Shift = 5) | Same arrow key moves a point by a grid step, a unit, a fifth, or a conic position; Shift means 1 unit, 5 steps, or nothing | one selected-point key handler with a shared step and Shift multiplier declared per graph
2. Drag snap grid differs | CrossRatioGraph.tsx:240-252 with crossRatioEdit.ts:14,22 (integer round, silent clamp at 30); FivePointGraph.tsx:336+ with fivePointEdit.ts:8-12 (1/5 round); polePolarEdit.ts:14 (1/5); PointSetGraph.tsx:578-596 and PointInPolygonGraph.tsx:480-483 (grid exponent); BaseCurveGraph.tsx:341-347 (no snap) | The same drag lands on different grids, and only some drags snap | shared drag-snap helper taking the graph's step, with one rule for free curve drags
3. Out-of-range drag gives different feedback | PointSetGraph.tsx:595 calls apply(refused), which shows a notice (apply, lines 167-175) vs crossRatioEdit.ts:22 clamps silently | Drag past the limit shows a message on PointSet and nothing on CrossRatio and FivePoint | one drag-limit rule (spec Decision 3: stop at limit, no message)
4. Vertical arrow silently ignored on constrained points | PointSetGraph.tsx:248 and pointSetModel.ts:204 (intervals); crossRatioEdit.ts:24-25 returns model unchanged for A-D, while comment crossRatioEdit.ts:36 says vertical is ignored | Up/Down does nothing with no feedback, the same as an unconstrained point does not | one constrained-point rule for keyboard nudges
5. Delete and Escape keys on selected point | PointSetGraph.tsx:520-531 (Delete/Backspace removes, Escape cancels pending); PointInPolygonGraph.tsx:430-432 (Escape deselects query); no Delete in CrossRatio, FivePoint, Pascal, PolePolar | Delete removes a point only on the set graph | shared selected-point keymap
6. Hover cursor on draggable points | bindMovablePointCursor used in BaseFunctionGraph.tsx:602, CorrelationGraph.tsx:336, AbstractJXGPointControlledCurve.ts:590; never called in PointSetGraph.tsx:662-676, CrossRatioGraph.tsx:321-331, FivePointGraph.tsx:508-518, PascalGraph.tsx:460-470, PolePolarGraph.tsx:449-452 (grep: no cursor in compgeo or projective) | Draggable points show a pointer cursor in function and curve graphs only | bind the cursor in one shared point factory
7. Refit after a typed edit outside the view | InterpolationGraph.tsx:176, HermiteGraph.tsx:180, SubdivisionCurveGraph.tsx:232, CorrelationGraph.tsx:186 refit; SimsonLineGraph.tsx:38 and InversionGraph.tsx:40 never rescale and report outside the view; PointSetGraph.tsx has no setBoundingBox; PointInPolygonGraph.tsx:235 refits only on loadFigure | The same out-of-view edit moves the view on some graphs, is reported on others, and is ignored on others | one view policy for typed and drag edits
8. Fit button algorithm differs | BaseGraph.tsx:713-744 fits all visible board points; BinomialNormalGraph.tsx:100-101,209 fitToBars and DensityAreaGraph.tsx:86-87,164 fitToCurve both use data-action fit-view; BaseFunctionGraph.tsx:229-230 and BSplineBasisGraph.tsx:82 override fitView | One label, several framings; a user cannot predict what Fit will show | one Fit action in BaseGraph with the graph supplying bounds only
9. Shift or Page big-step differs for value nudges | InversionPanel.tsx:177-228 (Shift x10); SimsonLinePanel.tsx:142-149 (Shift or PageUp x10); InscribedAnglePanel.tsx:82-86 (PageUp/PageDown); EpicycleGraph.tsx:514-517 and FourierCoefficientsGraph.tsx:384-387 (Shift with Up/Down only) | The same big-step key differs by panel; these are value steppers, so C5 and C13 overlap | one stepper keymap in CountSetter and Slider
10. Board-point keyboard reach | keydown listeners exist on PointSet, PointInPolygon, CrossRatio, FivePoint, Pascal, PolePolar, ThreeViews (angle), HullRobustness (cells); none in BaseCurveGraph.tsx:239-241 or the function graphs (grep: no keydown) | Arrow keys move points on eight graphs and not on curve or function boards | not determined whether curve boards offer another keyboard path; check PointCoordinateEditor (C4) before deciding

Not checked (budget): Parametric fitToCurve button, zoom and pan keys, selection highlight and hit-testing order, InscribedAngle glider drag, Inversion point drag, patch surface drag.
