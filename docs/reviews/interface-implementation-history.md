## Demonstrations opening comparison

A development-only comparison offered three real-route openings: A, one animated Bézier feature beside five links; B, six vertically ordered illustrated entries; and C, a large animated graph above six links. The owner selected C. Its refined form became a manual one-line carousel with route-specific preview, title, prompt, and graph/lesson actions. The production [opening-carousel spec](../specs/demonstrations-opening-carousel.md) later selected automatic advancement until user interaction and owns the live behavior.

The refined C prototype was checked at 1440, 810, and 390px for one-line labels, direct and keyboard selection, selected state, image/route changes, choice scrolling, no initial jump or page overflow, previous/next controls, and reduced-motion entrance behavior. The latter remained development-only. Its initial A/B/C captures were comparison evidence; the selected refined C captures remain at `docs/prototypes/demonstrations-carousel-C-{1440,810,390}.png`. The selection/refinement source is commit `c6a2155` on `codex/prototype-demonstration-motion`.

## Workspace selections and tool controls

The owner selected workspace variant B on 2026-10-08: a framed learning workspace with short exploration prompts and a separate topic rail, applied to all 26 demonstrations and their matching starting page. The design grouped navigation by mathematical family, kept the graph prominent, retained keyboard-accessible editing disclosures and real presentation controls, and preserved Slovenian/English support. Browser-local presets and figure export remained real production controls; the prototype-only simulated save/recovery UI was excluded. The choice is preserved at `375d453` on `codex/workspace-prototypes`. Its prototype's save/import/recovery panel was only an in-memory illustration; production uses real browser-local preset and figure-export controls. The prototype comparison passed TypeScript/build and browser checks of all workspace/home variants at 1440 and 390px, selected Bézier controls, PH hodograph, switching stability, and mobile dock/fit-view. Physical touch, projector readability, export fidelity, and formal accessibility review remained unverified. The [learning-workspace review](learning-workspace.md) and [current library/control specs](../specs/demonstrations-library-redesign.md) own relevant implemented evidence.

An earlier tools visual exploration was a proposal, not a production contract. Its rationale was that related controls were split between side panels, small-screen tools pushed the graph down, presentation controls depended on hover, “Povečava” ambiguously changed element size, and demonstrations expose materially different controls. It recommended a central graph with topic navigation and a grouped inspector, borrowing optional parameter guidance and explicit presentation controls; for narrow screens it proposed graph-first tabs. The static mockups were illustrative and did not wire real mathematics or persistence. The maintained [tools usability redesign spec](../specs/tools-usability-redesign.md) owns the accepted implementation scope.

The later compact-controls prototype selected C's square proportions over A's round controls and B's original large controls. Quieter panels, tools-on-demand, and bottom-tray layouts were rejected because they reduced control visibility. The accepted implementation kept the graph-centered workspace, topic navigation, prompts and inspector groups; compacted controls to 34px minimum desktop button height with 2px corners and 44px touch targets on narrow/coarse-pointer layouts; aligned switch rows; and refined slider bounds and collapse affordance. Its comparison is at `9886c8d` on `codex/prototype-calm-tools`. Five workspace tests and production build passed; browser review covered Bézier, switch label/Space activation, 390x844 layout, PH controls, save controls, and presentation entry/exit. Physical-device and projector review remained open. A scrollbar-gutter adjustment removed a ResizeObserver warning in two fresh-page PH selection checks and through presentation toggling. See the [demonstration-controls UX spec](../specs/demonstration-controls-ux.md) and [current architecture](../current-architecture.md).

## Shared workspace visual identity and limits

The accepted shared-workspace treatment used a cream canvas, quiet grid and botanical detail, sans-serif heading, green graph rail, ochre inspector/lesson accents, and restrained rounded panels/shadows. It kept the graph surface, geometry, routes, controls, lessons and storage behavior; presentation mode hides the botanical and retains its dark background. On `067c814` plus the workspace changes, 11 workspace tests passed, as did TypeScript/build and the existing production workflow and picker suites (nine tests). Browser checks at 390, 724 and 1440px in Slovenian and English found no document overflow, and covered polynomial, rational, spline C1 and cubic PH views, graph updates, auxiliary PH controls, keyboard navigation, inspector tabs, lessons, and presentation controls.

**Acceptance remains partial:** enlarged-text behavior was not verified because the browser zoom action timed out without applying zoom. Physical touch, actual classroom projection, comprehensive accessibility, and hosted CI/deployment were not verified locally. No mathematical or performance claims were made. This limitation is preserved from the original acceptance record and is not cleared by this consolidation. See [current architecture](../current-architecture.md), [graph visual style](../specs/graph-visual-style.md), and the [workspace review](learning-workspace.md).

## Count values

The Bernstein degree input originally had a larger minimum width than its wrapper, so its right-aligned value overlapped the plus button. The durable invariant is: **the editable count value must remain fully visible between the decrement and increment buttons at narrow, intermediate, and desktop widths, including enlarged text.** The specific report measured 614px: value `1`, input width 88px, wrapper width 56.06px, overlapping. The handler's primary evaluation records acceptance at 12:39 UTC: 21 numeric-control tests, typecheck, and production build passed; browser checks passed at 390, 614, and 1280px including 200% text; independent smoke checks confirmed direct input, button, and keyboard changes updated the graph. The current regression reference is `tests/count-setter.smoke.spec.cjs`. These are existing results; no new acceptance run is asserted here.
