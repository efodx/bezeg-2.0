# W2 K1 evidence

## Typed point paths (spline and rational boards)
Workspace point list (`CurvePointControls`) renders only when `workspaceUsesStructuredEditing()` is true (`BaseCurveGraph.tsx:216-226`); only Bezier, Curvature, Envelope, Comb(cubic), Offset(bezier), PH override it. No spline or rational graph does, so none has a typed point path. Not wired: enabling it would add add/delete-point and a per-point model (weights, junction functions), a model change, so reported not done.
| Board | Typed path | Reason |
|---|---|---|
| C1, C2, Cn, G1, G1Symmetric splines | none | free points only; junctions function-bound; b_i sliders are parameters |
| Rational Bezier, Decasteljau, Subdivision2, Elevation, Extrapolation, FarinPoints, CircleN | none (weights typed) | list needs structured editing plus weight per point |
Decision needed: opt these into the workspace list (needs add/remove semantics with weights) or accept the typed gap.

## Whole-curve move
Intended mechanism: `CurveEditingFeature.handleDown` (`CurveEditingFeature.ts:88-100`) in MOVE_CURVE mode gives a selected curve the pointer when it is inside `isMouseInsidePaddedBoundingBox` (`AbstractJXGPointControlledCurve.ts:425`, `processMouseDown` :230-235 starts drag/resize/rotate). Control points lie inside the frame, so a drag starting on one moves the curve; the option is named "manipulate_curve". The hint text lists "drag a control point" first, which a selected curve contradicts. Not fixed (no defect shown; changing it alters the mode). Suggest: hint wording, or deselect-first.
