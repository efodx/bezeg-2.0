## Open items

**Item 3: Show all against host Fit (read from code).** Not equal in general; equal on Notable, not on EulerLine.

- Host Fit (`base/BaseGraph.tsx:729-741`) collects every visible JSXGraph point (`JXG.isPoint(object) && object.visPropCalc.visible`) and passes them to `fitView`, whose default is `fitBoundingBox` (`:711`); it applies `setBoundingBox(box, this.equalAxisUnits, 'update')` and `applyZoom()`. `equalAxisUnits` is true (`BaseGraph.tsx:362`) and neither graph overrides it or `fitView`.
- Notable `showAll` (`compgeo/NotablePointsGraph.tsx:102-120`) takes the three vertices plus each centre whose overlay is on and that has a board place, then calls the same `fitBoundingBox` with the same box arguments and `applyZoom()`; it additionally calls `refreshOutside()`. The only JXG points on that board are the vertices and the centre markers (`NotablePointsGraph.tsx:275-282`; altitudes, bisectors and circles are lines or circles). For a degenerate triangle both frame the vertices plus the centroid only (the other centres are undefined, `compgeo/notablePointsModel.ts:118-119`; the incentre/circumcentre/orthocentre overlays draw nothing then, `:283-288` of the graph). So the point sets are equal on Notable: Show all = Fit, except that Show all returns early with fewer than three vertices where Fit still frames the vertices present, and the `refreshOutside()` call (the host presumably refreshes on the view event; not verified). I did not find a state where the boxes differ.
- EulerLine `showAll` (`EulerLineGraph.tsx:106-120`) adds H, G, O, N by `placeShown` (`:91-93`: N when the circle overlay is on; H, G, O when the centres overlay **or** the line overlay is on) and does not add the nine-point markers.
  - Concrete state 1 (nine-point markers): obtuse triangle with the nine-point overlay on (`ninepoints`, default off `:157`). The feet of the altitudes from the acute vertices lie on side extensions outside the vertex box; `drawNinePoints` creates real JXG points (`:253-262`) so Fit frames them and Show all does not.
  - Concrete state 2 (line without markers): centres overlay off, line overlay on, a very obtuse triangle with H and O far away. `placeShown` is true so Show all frames H, G, O, but no JXG point exists for them (`marker()` is only drawn by the `centres` overlay, `:197`), so Fit ignores them.
  - Degenerate or fewer than three vertices: Show all button is not rendered (`EulerLinePanel.tsx:23-37` render it only in the triangle branch) while Fit still works.
- Proposed answer to the spec's "Show all is removed if task 0 finds it equal to Fit": Notable yes (remove, with the `refreshOutside()` check), EulerLine no (the difference is the nine-point markers and the line-only H, G, O). Either keep Show all on EulerLine, or supply the Euler rule through a `fitView` override that also takes the shown places (the hook already exists, `BaseGraph.tsx:711`, overridden by `HullRobustnessGraph.tsx:304`). A `fitView` override only receives visible JXG points, so it would have to read `this.analysis()` itself, as `showAll` does.

## Exception candidates

- **Voronoi / DegenerateSites Reset view** and **Fortune Reset view**: the shared control would be host Fit. Technical reason: Fit frames visible JSXGraph points (`BaseGraph.tsx:729-741`), but these graphs frame the drawing's own box (the Voronoi `frame` via `viewBox()`, the Fortune run box with the circle bottoms, `FortuneGraph.tsx:228-238`) and then reset `followBox` so the drawing returns to that exact box. Alternative to an exception: a `fitView` override that returns the box (precedent: `HullRobustnessGraph.tsx:304`), which needs the hook to see the run; propose this, and record the exception only if the override cannot read the run.
- **Segment rows and interval rows** (BentleyOttmann, IntervalSweep): each row edits a pair or an endpoint pair; already listed in the spec.
- **Pascal ◀ ▶ stepping**: listed; stepping moves along the direction table (wraps modulo the table, `pascalEdit.ts:21-29`), not a coordinate.
- **Triangulation edge select and Flip, PolygonArea Reverse**: one-family domain actions (the spec's "not catalogued" rule); only C6 and C7 apply.
- **Query point in PointInPolygon and Voronoi**: a free point with its own typed path; not an exception, but it needs the C1/C4 point-list props for a single point (no add/remove).
- **ThreeViews c slider**: tenths in -25..25; keep `Slider` with a step (not an exception; the angle slider is the same).
- **Simson, Inscribed, Inversion angle fields**: cyclic 0..360; `Slider`'s optional exact field must wrap rather than refuse (decision 3 refusal does not apply to a cyclic value). Propose recording this as a named property of the shared slider, not a panel exception.

## Spec differences

- **C8**: the spec lists only `NumberInput` and the Simson/Inversion/InscribedAngle/PointInPolygon raw fields as per-keystroke. The `IntegerField` in PS (`PointSetControls.tsx:70-74`), the CrossRatio `IntegerField` (`CrossRatioControls.tsx:27-45`), FivePoint `CoordinateField` and PolePolar `StepField` also commit on every change; they are not Enter or blur fields. Voronoi's `QueryFields` is Enter or the Set button, as the spec says.
- **C18**: the spec says PointSet refuses with a notice at the limit and CrossRatio clamps silently: confirmed. It does not say that FivePoint, PolePolar and ThreeViews also clamp silently, nor that PointInPolygon and Voronoi query points refuse with a message on drag.
- **C16**: the spec says CrossRatio steps "one unit". Confirmed, with no Shift key at all (`CrossRatioGraph.tsx:231-238`). Backspace also deletes in PS (`PointSetGraph.tsx:533`). Escape also deselects the query in PointInPolygon (`:430`). ThreeViews arrows need no selection.
- **C20**: Show all is not equal to Fit on EulerLine (item 3); it is equal on Notable.
- **C10**: the Euler/Notable/Simson/Inscribed/Inversion raw selects add a `custom` option only while active (Euler `EulerLinePanel.tsx:77`), a fifth form not in the spec's four (inferred for Simson, Inscribed and Inversion from `value={exampleId ?? "custom"}`).
- **C25**: FivePoint has three raw index `<select>`s (chord ends, third point, `FivePointControls.tsx:98-110`) that the spec does not mention; they choose points, so C14-like. Simson's epsilon is a second raw range with five discrete stops (`SimsonLinePanel.tsx:154-160`), not mentioned under C13.
- **C27**: Monotone counts steps from 0: confirmed for both Monotone panels; the other trace panels count from 1.
- **C12/C9**: Voronoi has own construction Next/Back/Reset (`VoronoiControls.tsx` construct group): confirmed. Spec "own Reset buttons in 10 files": in these directories only Fortune (view) and Voronoi (example, view, construction) have one; no other file here has a scene Reset button.
