# Step 7 slice 3: deterministic defaults for omitted fields

Status: in progress (see "Results" for observed checks).

## Changes

- `src/graphs/base/BaseGraph.tsx` `importPreset`: omitted `boardState` -> `startingBox` view; omitted `graphState` ->
  `replaceState({...getInitialState(), initialized: true})`; omitted `data` -> new `persistedDefaultData()` (default
  `cloneLessonValue(defaultPreset())`). A present `graphState` still merges over the live state, as before.
  Figure entry: `importFigurePresetData` uses `persistedDefaultData()`; `finish` sets the starting view when the checked
  Preset has no `boardState` (previously the selection path alone did).
- `src/graphs/base/BaseCurveGraph.tsx` `importPreset`: forces the no-selection state only onto a given `graphState`;
  an omitted one stays omitted (the initial state already has no selected curve).
- `persistedDefaultData()` overrides pinning the first example: `BSplineNurbsGraph` (circle), `BSplineInsertionGraph`,
  `BSplineExtractionGraph` (quadratic). `defaultPreset()` (Reset, lessons) is untouched and still follows the chosen example.
- `BSplineNurbsGraph.figurePresetGraphState`: `t` is the merged (Preset or initial) `t` clamped into the new domain, not the live `t`.
  The importer's `this.state.t` clamp stays: on a persisted entry the state was just replaced, so it reads the Preset's or initial `t`.
- `BaseFunctionGraph.initialView()` returns the example/default box, so a view-less Preset on a function graph gets the same
  view `initialize()` gives a fresh scene.
- Spec: "Implemented, slice 3" paragraph in `docs/specs/lesson-authoring-architecture.md`.

Not changed: Blossom/DeBoor/Insertion figure-state merges (they read the just-imported data, deterministic); trusted
checkpoints, lesson fixture and default-scene paths; mount without a selected Preset (`initialPresetData`).
