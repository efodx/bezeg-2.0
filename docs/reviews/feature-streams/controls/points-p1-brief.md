**Acceptance** (all in `src/graphs/base/points/`, no React; only `pointFactory.ts` may import JSXGraph types)

1. `placement.ts` — `placeNewPoint(points, {at?, rule?, limit?})` (decision 1): explicit `at` wins exactly; else the graph's `rule(points)` if given; else one unit right of the last point, or one unit left when that passes `limit.max` on x; an empty list without `at`/rule places at the origin. Points are `readonly [number, number]`. Pure, returns the new point; it does not validate the graph's mathematics.
2. `viewPolicy.ts` (decision 6, task-0 decision 5) — `isOutsideView(box, framed)` for a JSXGraph box `[left, top, right, bottom]` (either orientation, as `InterpolationGraph.editPoint` handles today) and a list of framed points; `refitWhenOutside(box, framed, refit)` calls `refit` only when some framed point is outside, and returns whether it did. Doc comment: an add or typed edit calls it with everything the graph frames for the new point (e.g. Hermite tangent tips); a drag never calls it.
3. `dragConstraint.ts` (decisions 3 and 7) — `constrainPoint(raw, {step?, bounds?})`: snaps each coordinate to the step (half away from zero, as `NumberInput`'s snap, decision 16) and clamps silently to per-axis bounds `{x?: [min, max], y?: [min, max]}`, the clamp keeping the result on the grid when the bounds are on it. No notice type exists here: a mathematical refusal stays the graph's (doc comment says so). Also `stepPoint(point, delta, options)` = constrain(point + delta), the keyboard nudge (decision 7: behaves like a drag).
4. `pointKeys.ts` (C16) — `pointKeyCommand(event, {step, bigStep?, axes?: 'xy' | 'x'})` returns `{kind: 'move', dx, dy}` for arrows (Shift = big step, default `resolveBigStep` from `src/inputs/stepKeys.ts`; Up is +y), `{kind: 'remove'}` for Delete/Backspace, `{kind: 'back'}` for Escape, undefined otherwise and for any Alt/Ctrl/Meta chord. With `axes: 'x'`, Up/Down return undefined. Reuse `stepKeys.ts`; do not duplicate its big-step rule.
5. `pointFactory.ts` (C18) — `createMovablePoint(board, coords, attributes)` creates a JSXGraph point and binds the cursor with the existing `src/graphs/base/bindMovablePointCursor.ts`; returns the point. Keep it thin; no callers yet.
6. `index.ts` re-exports the five. Unit tests `*.test.ts` beside them cover every rule above, including: placement at the limit, empty list, `at` beating `rule`; view box in both orientations, a point exactly on the edge counting as inside; snap half-away-from-zero for negatives; clamp keeping grid; Shift big step; `axes: 'x'`; modifier chords ignored. `pointFactory` gets one test with a fake board (see how `bindMovablePointCursor` is tested or used in tests; a JSXGraph test board exists in `src/graphs/base/realGraphTestHarness.tsx` if a fake is awkward).
