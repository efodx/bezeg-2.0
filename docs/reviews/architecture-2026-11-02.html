01 / in-process

Validate the whole Preset at every restore seam

StrongStatic correctness finding
src/graphs/base/BaseGraph.tsx:637,647,915,1057
src/graphs/base/presets/PresetImport.ts:46
src/graphs/curves/interpolation/interpolationPresetCollection.ts:41
src/graphs/curves/interpolation/InterpolationGraph.tsx:103

Problem. The collection module has validation depth, but the local restore adapter bypasses part of its interface: unchecked persisted scene state can overwrite valid data.

Solution. Concentrate complete persisted-Preset validity in one restore module shared by file import, local selection and figure capture. Keep trusted in-memory Lesson checkpoints distinct.

  • Locality: one validity decision
  • Leverage: every persisted entry
  • Interface becomes test surface
Evidence, responsibility and test direction
  • PresetImport.ts:46–48 invokes collection.checkGraphState. BaseGraph.tsx:637–644 checks only data; :647–652 overlays raw graphState, reached at :1057 during figure restoration.
  • Concrete example: valid interpolation data plus graphState: {points: 3}. File preflight rejects it; local figure restore overlays it before initialize. InterpolationGraph.tsx:103–119 reads state.points.length and passes state.points to InterpolationScene. No repair override exists in this graph.
  • This is static path analysis, not an executed failure reproduction. The expected consequence is a broken Demonstration during corrupt local Preset restoration, rather than the actionable rejection used for files.
  • The host gap is inherited; interpolation validation added in 21e0454a and expanded in 7602bb93 on 31 October exposes it in new work. The integration mistake is testing the collection without establishing that every persisted restore caller invokes its rules.
  • Deletion test: removing validation redistributes useful rules into callers. Deepen its use. Two real adapters justify this seam: file preflight and local restore.
  • Test through the restore interface with equivalent valid and invalid file/stored Presets, including figure batches. Direct collection tests cannot prove caller integration.
  • Consistent with ADR 0016 shared collection validation and ADR 0015 replacement order. B-spline and projective graphs repair duplicated state differently; this example must not be generalized to every family.
02 / in-process

Make Guided example lookup flow in one direction

StrongArchitectural debt; no observed failure
src/learning/runtime/lessonCatalog.ts:2,163–175
src/learning/content/chapterOwnedLessons.ts:34–59
src/learning/content/*ChapterRegistry.ts
src/learning/chapter/guidedLessonOwnership.ts:13–138

Problem. The lookup module leaks initialization knowledge across a circular seam: eight registry adapters repeat lazy getters while chapter ownership is assembled from overlapping sources.

Solution. Separate authored lesson adaptation from chapter ownership resolution. Compose family facts once and keep compatibility routing inside a deep Guided example resolution module.

  • Locality: ownership with chapter facts
  • Leverage: all entry adapters
  • Depth: hide lookup ordering
Evidence, responsibility and test direction
  • lessonCatalog.ts:2 imports chapterOwnedLessons, whose table imports registries. Eight registries import getCatalogLessonForDemonstration back from the catalog and use Object.defineProperties getters. Their comments explicitly explain the cycle workaround; chapterOwnedLessons adds thunks to postpone access.
  • The pattern is visible in 362d2015 (convexity, 1 November) and copied into 8f4118d3 (triangulation) and 29a55b03 (numerical methods, 2 November), among others. This is recently multiplied integration debt, not a demonstrated runtime failure.
  • guidedLessonOwnership.ts:128–138 combines primary, additional, family, retained and chapter-owned sources. Legacy compatibility and many-to-many ownership are useful behaviors; do not erase them just to reduce file count.
  • Global test edits amplify friction: guidedExamplePreviewCopy.test.ts:23,28 pins 81 Lessons and 88 copies; Routes.test.tsx:97 and demonstrations.test.ts:99 pin 82 Demonstrations. Geometry handoff 32 explicitly warns of count-test rebase conflicts. Prefer exact coverage/uniqueness relationships for growing catalogs, retaining intentional historical baselines.
  • Deletion test: deleting a registry just moves useful facts. Remove circular adaptation and repeated load-order scaffolding; do not add a forwarding module. The seam already serves real Learn and catalog adapters.
  • Test canonical/legacy links, requested and default chapter owners, missing/duplicate entries and initialization order through the caller interface.
  • Fits ADRs 0002 and 0014. A9/A10 already removed old action translation and derived availability; those improvements should be preserved.

Give Trace playback one lifecycle owner

Worth exploringDuplication; no current drift found

Problem. Controller timing has depth, but each graph adapter still implements the same lifecycle interface across remount, unmount, Lesson transition, capture and scene replacement.

Solution. Concentrate the repeated lifetime protocol in one module. Keep algorithm transitions, step intervals and selection behavior local; decide the seam before choosing composition or inheritance.

  • Locality: lifetime rules together
  • Leverage: five actual adapters
  • Interface: direct capture checks
Evidence, responsibility and test direction
  • The five named code blocks recreate a disposed controller on remount, dispose on unmount, and pause on Lesson transition, figure capture, figure-scene disposal and scene replacement. HullTraceGraph.tsx:251–282 and DelaunayGraph.tsx:283–318 show the repeated protocol.
  • The copies currently agree. No behavioral drift or timer failure is established. This does not justify imposing a universal graph superclass.
  • Hull has algorithm-dependent timing; Delaunay clears triangle selection. Keep these differences graph-owned. IterativeFunctionGraph demonstrates sharing lifecycle beyond controller timing in another family.
  • Deletion test: removing a lifetime block loses behavior. Moving it into a shallow forwarding module earns nothing; the depth should remove callers’ obligation to remember all stop paths.
  • The sampled host tests cover remount and cleanup. The five trace graph test files do not directly target beforeFigureCapture/pausePlayback; verify actual export pause behavior through the same interface as callers and retain Next-step/playback equivalence.
  • Respects ADR 0012 and synchronous Lesson scene actions. No mathematical, renderer or stored-format change is proposed.
