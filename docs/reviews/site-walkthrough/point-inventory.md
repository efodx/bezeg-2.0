## 3. Interval Sweep and blossoming

### Interval Sweep (M02 cursor, M01 labels): `src/graphs/compgeo/IntervalSweepGraph.tsx`

- `IntervalSweepGraph extends PointSetGraph<IntervalSweepOverlayId>` (:43). It creates no draggable point itself; its two `create("point")` calls are fixed overlay marks with `withLabel: false` (:297-298 `sweep-pair-mark`) and the endpoint-less curves (:256-258).
- The draggable points come from the inherited `PointSetGraph.createDrawn` (`PointSetGraph.tsx:798-824`): `board.create("point", [at.x, at.y], {name: this.pointName(i), withLabel: true, size, face: "o", showInfobox: false, fillColor/strokeColor/strokeWidth callbacks, highlightFillColor, label: {visible: () => displaySettings.pointLabelsVisible, offset: [8, 8], strokeColor: GraphPalette.label}, layer: 7})` (:803-810). Not passed: `fixed` (so draggable, JSXGraph default), `useMathJax`, `parse`, `fontSize`, `cssClass`, `styles.point`. Listeners: `down` :811, `drag` :816, `up` :818.
- Cursor root cause: `PointSetGraph.tsx` never imports `bindMovablePointCursor` (grep: zero references in `compgeo/`). So all 22 point-set graphs (`compgeo/*` on `PointSetGraph`) have no hover cursor.
- Label root cause: the label is a JXGraph default point label (plain text, JSXGraph default font size, since `fontSize` is absent and the display setting is ignored), name `P1`, `P2`... (:423), not `$$p_{i}$$` through `useMathJax: true`. The interval/segment texts at :835-837 and :849-851 are `display: "internal"` (SVG text) with a hard-coded `fontSize: 14`, no `useMathJax`. Both look unlike the MathJax labels of the curve and function graphs (`styles.point`, `PointStyles.ts:54-64`).
- Smallest change to the shared path (proposal, not made): in `createDrawn` call `bindMovablePointCursor(point, board)` once after :810 (one import and one line; fixed points are already skipped by its `visProp.fixed` test), and spread the shared label attributes into :808, i.e. `label: {...stylesForBoard(board).point.default.label, visible: ..., offset: [8, 8], strokeColor: ...}` with the name written as `$$P_{i}$$` (or `$$P_1$$` form) from `pointName`, keeping `parse: false`. Subclass renames (`FortuneGraph` A, B, C; curve-pair board names) go through the same `pointName` override. The interval texts (:835, :849) need `useMathJax: true, parse: false` and the display font size instead of 14. The subclass overrides of `pointName` and any test that reads `point.name` or `label.plaintext` would change (unverified which tests).

### Blossoming / polar form: `src/graphs/curves/bspline/BSplineBlossomGraph.tsx` (scene `BSplineBlossomScene.ts`)

- The graph holds no point code; the scene `BSplineBlossomScene` (declared in `BSplineBlossomGraph.tsx:125-146`) builds everything.
- Draggable control points: `new JXGBSplineCurve(...)` (`BSplineBlossomScene.ts:47`), whose points come from `createEditableInputPoint` with `this.styles.point.pi(i, ...)` (`JXGBSplineCurve.ts:84`, `AbstractJXGPointControlledCurve.ts:572-590, 612-625`). These are already on the shared path: cursor bound (:619) and `$$p_{i}$$` MathJax label. The drag handler is added at `BSplineBlossomScene.ts:126-129`.
