# JSXGraph corrected triangle and teapot confirmation

Chromium 156.0.8078.4, JSXGraph 1.14.1, desktop 1440×1000, iso8/tiling8. The focused [verifier](../../prototypes/bezier-patches/verify-jsx-final.mjs) ran against the pinned isolated preview. Served and local `prototype.js` SHA-256 agree: `9038ca9671a2d90a36069714fd8fb187c657ba10aad5766dc988bf9e443e6f07`. This is the unchanged JSX prototype from the previous batching work, not a new renderer repair.

- All 64 actual `polygon3d` owners have substantive rendered SVG `points` attributes. All 64 changed before pointer release, with point0 changing and camera fixed. This closes the old null-`d`-attribute probe gap; polygons use `points`, not a path's `d` attribute.
- Exactly 32 actual teapot `surface3d` owners have substantive rendered paths. Each owner's X/Y/Z at three parameter pairs agrees with independent bicubic Bernstein sums over the reviewed fixture, maximum absolute error `8.88e-16` (threshold `1e-10`). The single-patch editable net is absent, the parameter domain is hidden, and returning restores 16 editable points and one tensor surface.
- Browser page errors were empty. The handler inspected [the triangle during drag](jsx-final-2026-10-26/triangle-during-drag.png) and [the 32-patch teapot](jsx-final-2026-10-26/teapot-32.png). These images establish visible geometry, not a new four-view depth-order verdict.

[Raw report](jsx-final-2026-10-26/report.json) retains actual owner IDs, rendered attributes and sample errors. The [initial probe failure](jsx-final-2026-10-26/initial-probe-failure.json) is retained: the verifier first treated JSXGraph's homogeneous `F()` result as affine coordinates, producing non-finite errors and correctly failing. Using the actual owners' X/Y/Z accessors fixes this verifier assumption. No prototype mathematics changed.

The earlier JSXGraph PNG taint, touch-z XY drift and accumulating listeners remain recorded in [functional evidence](prototype-functional.md). They have not been repaired or declared passing. They are limitations of the default candidate for the renderer decision, rather than reasons to keep productionizing a throwaway prototype. Four-view depth acceptance remains unestablished for JSXGraph. Neither prototype has keyboard parameter sliders; these are explicit adapter/UI acceptance work required by the spec, not evidence that either renderer cannot support ordinary DOM sliders. These dispositions do not waive production interaction/export/lifecycle requirements.
