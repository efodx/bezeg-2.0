## 10T-B — reuse scene geometry on camera-only changes (bezeg-worker, owns `src/graphs/patches/BaseSurfaceGraph.tsx` and a new or existing test file for it only)

- Problem (task 07 review #9): every orbit pointermove writes `camera` to state; `onStateChange` → `reconcileView` → subclass `buildScene` re-samples every iso, boundary and mesh vertex although `revision` is unchanged.
- Implement in the base class only: keep the last built scene with its `revision` and selected point; when the revision and selection are unchanged and the state change is camera-only (every state key other than `camera` is `===` to the previous state), reconcile `{...lastScene, camera: <the camera buildScene would produce>}` without calling `buildScene`. First verify how subclasses derive `scene.camera` from state (grep `camera` in the `*Scene.ts` builders); if any builder transforms it, reuse that transform rather than copying state blindly, or limit reuse accordingly and say why. Any other change still calls `buildScene`. Invalidate the cache on view (re)creation, `syncReplacedScene`, `redrawGeometry` and disposal.
- **Tests**: with `FakeSurfaceView` and a spy on `buildScene` (any concrete tensor graph): an orbit (camera edit) does not call `buildScene` and the view receives the new camera with the same geometry arrays; a `u`/marker-only change, a selection change, a Preset restore and a geometry change all call it. Mutation: disable the reuse and the identity assertion fails; make reuse ignore a non-camera key and a test fails.
- **Checks**: the test file, `src/graphs/patches/*.test.tsx`, `npx tsc --noEmit --pretty false`, `npx eslint` on your files. Logs `.command-logs/t10tb-*.log`.
