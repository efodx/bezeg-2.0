# Renderer spike mathematical review

Scope: read-only review of the JSXGraph and three.js prototype geometry against [the renderer task](../../tasks/bezier-patches/02-renderer-spike.md) and [the rendering contract](../../specs/bezier-patches.md#rendering-and-interaction-contract). No renderer recommendation.

- **P1 — JSXGraph tensor control net omits each final endpoint.** In `prototype.js:114-115`, the line sampler maps `s=1` to `Math.min(2, floor(3s)) = 2`, and its interpolation fraction is `3s % 1 = 0`; it therefore returns control index 2 instead of index 3. The three.js `tensorGridLines` uses full endpoint-to-endpoint polylines (`three-prototype.js:26`). Use an explicit piecewise sampler that returns the last control at `s===1`, or construct the four-point polyline directly.
- **P1 — JSXGraph triangular iso-curves duplicate one family.** `prototype.js:104-105` uses `(u,v)=(t(1-s),ts)` and its coordinate swap `(ts,t(1-s))`; both trace the same constant-`u+v` line in reverse. At each `t`, the independent constant-`u` and constant-`v` families are missing. Three.js currently draws only the constant-`u+v` family at `three-prototype.js:28`. Render the three barycentric families consistently before comparing iso-grid cost or appearance.
- **P1 — 32-patch performance scenes are not comparable.** JSXGraph's `state.stress` path repeatedly draws translated copies of the current preset patch (`prototype.js:97`), while three.js draws the 32 distinct teapot patches from source-indexed control points (`three-prototype.js:31-33`). Match actual teapot data and patch count in both renderers, or label the repeated-patch scene as a separate synthetic load test and exclude it from teapot comparisons.
- **P2 — triangular domain meshes are sound.** The JSXGraph mesh samples lattice points `(i/n,j/n)` for `i+j≤n` and emits the elementary triangle plus its second half where present (`prototype.js:80-85`). Three.js uses the same lattice and split (`three-prototype.js:23`). These partition the reference simplex with no gaps or overlaps. The JSXGraph parametric map `(s,t)→(s(1−t),st)` also covers it, but uses a collapsed square grid; compare its tessellation cost with the triangular lattice as different mesh strategies, not equal triangle counts.
- **Math fidelity otherwise:** both evaluators use cubic Bernstein weights in the spec's canonical triangular order (`prototype.js:14-23`, `three-prototype.js:10-15`); the visible construction executes the corresponding tensor or barycentric de Casteljau recurrence (`prototype.js:124-138`, `three-prototype.js:30`). Boundary parameterizations agree with the patch edges. The three.js teapot resolves its patch indices into the extracted source xyz coordinates (`three-prototype.js:31-32`); the existing independent source evaluator is adequate evidence for that fixture, so it was not rerun.
