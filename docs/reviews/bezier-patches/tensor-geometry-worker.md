## Convention and implementation

`TensorProductBezierPatch` stores `net[i][j]`, with the first index advancing in `u` and the second in `v`. Evaluation applies the curve kernel along each row in `v`, then to those row results in `u`. This agrees with the reviewed teapot source convention: `(0,0)`, `(1,0)`, `(0,1)`, `(1,1)` map to `P[0][0]`, `P[m][0]`, `P[0][n]`, `P[m][n]`.

The implementation supports rectangular bi-degrees 1–4, the separate bilinear recurrence, a two-stage scheme, live iso-curves and boundary curves, first/second partials and twist, normalized normals, per-direction subdivision/elevation, sampled rectangular meshes with explicit triangle faces, and control-net bounds. The direct recurrence records each simultaneous 2×2 reduction net through `min(m,n)` levels and the remaining univariate scheme. Returned iso/boundary curves retain the control-point references captured when created; they respond to edits of those points, while replacing the patch grid does not retarget existing curves. Mesh and bounds cache values are keyed by control-point versions and structural replacement; mesh results are copied to prevent callers from corrupting cached samples. Volatile function-backed points bypass caching. The engineering review flagged `eval()`'s mutable point result and cache growth for a separate repair slice; cache acceptance is pending that work. Degenerate normals and invalid dimensions, coordinates, parameters, directions, and mesh intervals throw explicit errors. Shared `BezierPatch` mesh data uses explicit faces and a variable-length boundary-curve list for the triangular implementation.
