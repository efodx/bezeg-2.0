## What changed in 03D

The 03C profile showed that orbit frames were bound by style, layout and paint, not by JavaScript.

- **`d` → `points`** (`69b7ecb`). In Chromium a path's `d` is a CSS property, so each write cost about 4 µs of style recalculation (46 ms per teapot move). Drawables are now adapter-owned `<polygon>`/`<polyline>` nodes in JSXGraph's layer group, written through `points`, which costs nothing in style.
- **Camera-only changes are drawn in the next animation frame again** (`973f521`). In an A/B on the same revision, visible latency was equal: tensor/triangular density 8 at 1 frame, density 16 at 2 frames (median). The synchronous draw instead held the pointermove task for 10–17 ms. The rAF draw also coalesces input that is not frame-aligned, such as wheel events. This reverses the gate's option-A item "draw camera-only changes synchronously"; ADR 0019 is amended in 07D.
- **Minimal-move reorder** (`7c1b0ee`, n − LIS), then **slot rebinding** (`7a47a55`). Teapot draws were bound by about 3250 `insertBefore` calls per frame: 9 ms of JS plus about 15 ms of style recalculation on the moved nodes. Now there is one fixed-order `<polyline>` slot per drawable. Each frame writes the k-th farthest drawable's geometry into slot k and rewrites a slot's attributes only when its style changes. Only point and marker ellipses still move. `applyDomOrder` became unused and was deleted with this record.
- Measured and rejected: React re-render on a camera edit (1–2 ms), a larger teapot stride, and whole-segment runs. None of them raised the teapot rate.
