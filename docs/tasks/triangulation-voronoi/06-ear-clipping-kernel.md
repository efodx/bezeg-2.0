Pure TypeScript in `src/compgeo/earClipping.ts` (no React, JSXGraph, localization or graph state), in the shape of `giftWrapping.ts`: payload of vertex indices into the input, running `predicateCount`, `noteKey` string literals, a pure fold and an `earClippingStateAt`.

1. Input: grid vertices (validated as the other kernels do), at most 40. Refuse, with a distinct reason value the graph can localize, non-simple polygons (`polygonSimplicity(vertices, true)`), fewer than three vertices, zero area and three consecutive collinear vertices (`orient` \(=0\) at any vertex). A clockwise polygon (negative `doubledSignedArea`) is reversed before clipping and the result reports `reversed: true`; output indices still refer to the caller's input order.
2. Ear rule (stated in the lesson, so it must be exactly this): scan the remaining cycle from its lowest remaining input index in counter-clockwise order; vertex \(v_j\) with neighbours \(v_i,v_l\) is an ear when `orient(v_i, v_j, v_l) > 0` and no other remaining vertex lies in the closed triangle (on the boundary blocks). Clip the first ear found, then rescan from the lowest remaining index. When three remain, output the last triangle and `done`.
3. Trace events: `test` per candidate apex (with the verdict and, when rejected, `reflex` or the first blocking vertex), `accept`/`output` per clipped ear, `done`. `predicateCount` counts `orient` calls. The fold gives the clipped triangles so far, the remaining cycle and the current candidate.
4. `threeColouring(triangles, n)`: colours \(0,1,2\) per vertex by walking the dual tree from the last triangle; each triangle gets three distinct colours. `guardClass` returns the smallest colour class (ties: lowest colour). `guardView(triangles, vertex)` returns the triangles containing that vertex (exact: a vertex sees every triangle it belongs to).
5. Tests (`earClipping.test.ts`), handler-checked numbers (script, 2026-10-31):
   - Notched pentagon \((0,0),(6,0),(6,4),(3,2),(0,4)\): ears in order \(\triangle(6,0)(6,4)(3,2)\), \(\triangle(0,0)(6,0)(3,2)\), last \(\triangle(0,0)(3,2)(0,4)\); vertices \(0\) and \(1\) are rejected first because \((3,2)\) lies on their triangles' boundary. Classes \(\{(0,0),(6,4)\},\{(3,2)\},\{(0,4),(6,0)\}\); guard class \(\{(3,2)\}\), size \(1=\lfloor5/3\rfloor\); its view is all three triangles.
   - Comb \((0,0),(18,0),(16,2),(15,6),(14,2),(10,2),(9,6),(8,2),(4,2),(3,6),(2,2)\): \(9\) triangles, class sizes \(4,4,3\).
   - Random simple grid polygons (\(n\le15\); generate e.g. by sorting random points by angle about an interior point, keep those `polygonSimplicity` accepts and that have no three consecutive collinear vertices; bounded count, a few hundred): \(n-2\) triangles, \(n-3\) diagonals, doubled areas sum to `doubledSignedArea`, every triangle CCW, no triangle contains another vertex in its closed region, every polygon edge is a triangle edge; colouring proper, smallest class \(\le\lfloor n/3\rfloor\); guard view equals the triangles at the guard vertex.
   - A clockwise input gives the same triangles (as index sets) as its reversal and `reversed: true`; each refusal case returns its reason; trace `stateAt` at the last index equals the final result; `clampTraceIndex` handles a stale index.
   - Observed failures under two deliberate mutations (for example open triangle test so boundary vertices do not block, which changes the pentagon order; restart scanning at the next vertex instead of the lowest index).
