## Motion pilots

The offline encoder is the installed FFmpeg (`ffmpeg`/`ffprobe` on PATH), using `libvpx-vp9`, CRF 34, zero target bitrate, `yuv420p`, silent output, 24 fps. No encoder or dependency is added to the application. Each pilot is 720×440 and three seconds, below 300 KiB. Generated WebM imports use Vite's `?no-inline`, guaranteeing separate media URLs even for small files.

Repeated subdivision replays independent exact checkpoints 0/1/2 (one/two/four pieces); bisection replays steps 1/2/3. Each state holds 24 identical PNG frames; no crossfade invents intermediate geometry. Bézier uses 72 deterministic samples, moving only the second original control point along `sin²(π phase) × (1.25,1.5)` and returning. Frame 0 precedes pointer down; intermediate frames use actual native pointer dragging; the final coordinate is restored exactly through the existing keyboard coordinate form. The other three points remain equal to their initial coordinates to `1e-9`; pointer targets alone allow subpixel quantization tolerance. The original curve's first/last path hashes agree. All samples use the poster's locked camera and the same annotation policy.

Capture stroke treatment caches the original width/opacity and disables capture-only CSS transitions; each motion sample asserts identical stroke widths. This closed a real diagnostic failure where repeated multiplication compounded a curve into a filled blob. That failing staging run was stopped before publication. Old `.command-logs/preview-staging-60708` motion frames are obsolete and must not be used as evidence. Current verified diagnostics are under `.command-logs/motion-verified-fast/`.

The fast pilot pass produced 10,616 bytes (subdivision), 17,802 bytes (bisection), and 25,612 bytes (Bézier), all three seconds. The final pass adds 125 ms per pointer sample. Comparing the two runs passed: all 72 Bézier actual point-coordinate arrays and curve-path hashes were identical, all discrete step counts/readouts agreed, and every camera agreed. This compares mathematical states/framing rather than requiring encoded-byte equality across encoder versions. Decoded middle-frame review (`.command-logs/motion-verified-fast/decoded-middle.png`) confirmed readable curve/polygon separation after compression. ## Explicit limitations

- Polynomial and rational extrapolation have a real moderate extension, but their existing runtime replaces the original control representation. Its endpoint marker then evaluates the extended curve again. Existing controls cannot retain an original-interval overlay; these stills do **not** claim to distinguish original versus extended parameter portions completely. Proposed disposition: accept this documented capture limitation or separately specify a two-panel comparison; no mathematical runtime change is included.
- Spline parameterization shows 12 genuine sample markers; the sample count exists in the inspector, not as existing board text, so the still does not print the number.
- Greedy rational weight-label selection omits crowded labels; it retains valid existing weight information without changing any weights.
- Local Chromium/Chrome/Edge availability does not imply physical device, projector, Safari/WebKit, Firefox, or screen-reader acceptance. The handler records actual player/browser coverage and deployed MIME separately.

## Regeneration

Run `just --list`, then `just build` and `just preview 3012` (or reuse an explicitly verified production server). Run `node scripts/capture-demonstration-previews.cjs` with `PREVIEW_BROWSER_EXECUTABLE_PATH` if Playwright's managed browser path differs. On this Windows installation the executable is `C:/Users/NonFriedMotherBoard/AppData/Local/ms-playwright/chromium-1248/chrome-win64/chrome.exe`; the sandbox's remapped LOCALAPPDATA is not the installed browser directory. A sandbox process restriction can require the authorized browser command to run with escalation.

`PREVIEW_BASE_URL` changes the served base; `PREVIEW_FFMPEG` and `PREVIEW_FFPROBE` select existing offline executables. `PREVIEW_IDS=id,id` creates diagnostic output and evidence only, never publication. `PREVIEW_SAMPLE_DELAY_MS` adds a delay between settled pointer samples to verify speed independence; it never selects mathematical state. A complete run requires the installed encoder and all 45 route outcomes to pass.

`PREVIEW_RECAPTURE_IDS=id,id` performs an explicit full-set update: it copies checksum-verified existing outputs into staging, replaces only selected posters, then revalidates the complete catalog/maps/manifest/motion set before publication. It requires identical source revision, mathematical-source fingerprint and presentation fingerprint; any changed remaining recipe also fails final validation. A global presenter or motion-helper change requires full generation. The one-time transition from the older manifest without a presentation fingerprint required explicit `PREVIEW_RECAPTURE_VERIFIED_PRESENTATION=1` after comparing the already-reviewed presenter; this is not an automatic cache fallback. Final delivered output was subsequently regenerated in full with the complete fingerprint contract.
