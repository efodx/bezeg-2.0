Gates: `G-FN`, `G-REG`. Depends on 03 and on Batch B being released.

1. **Measurement first.** Follow the [performance plan](../../performance-plan.md). Drag the initial point and the step control with 21×15 and 41×29 field grids, and compare per-segment JSXGraph objects, one polyline-array curve, an overlay canvas or SVG, and a coarse grid. Record frame times and the threshold used in `docs/reviews/numerical-methods/`. Then write an ADR that cites the measurement. No drawing code is merged before the ADR.
   *Measured 2026-11-03* with `scripts/euler-field-perf.cjs`: one JSXGraph curve for all arrows passes (about 1 ms per operation at 41×29); one segment per arrow does not (10 to 17 ms). See [07-field-measurement.md](../../reviews/numerical-methods/07-field-measurement.md) and [ADR 0037](../../adr/0037-direction-field-drawing.md).

It has a draggable or numeric initial point, discrete `h`, an end-value readout, an optional exact curve, and an optional step reveal through `IterativeFunctionGraph`-style playback. A divergent run shows a visible status. Every generated field object is disposed.
   *Accepted 2026-11-03*, unmounted: `src/analysis/eulerModel.ts` and `eulerField.ts`, `src/graphs/functions/EulerGraph.tsx`, the `euler` Preset collection and the `euler_ode_*` keys. The exact value and error are hidden when the exact solution has a pole at or before the end x or leaves the |y| ≤ 1000 bound; the step reveal resets on any edit that changes the polyline; no lesson actions yet. Engineering and mathematical reviews had no blocking findings; their repairs (note wording, exact bound, steps-taken readout, reveal reset, lifecycle and resize tests) are applied. Checks: tsc, eslint, `just unit src/graphs/functions src/analysis src/localization src/graphs/base`, and mutations of the reveal reset and exact bound failing the new tests.
