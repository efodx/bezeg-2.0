# 05 — Point-set/polygon graph

Status: planned. Source: [spec §2 point-set graph](../../specs/convexity-hulls-lessons.md#2-draggable-point-set-and-polygon-graph). Kind: F2a, engineering + UI/accessibility review. Depends on 02 (simplicity) and 04 (model). No route, catalog entry or Demonstration registration (that is F2b, gated by `G-REG`); no lesson actions yet (they wait for Platform A9a's typed lesson vocabulary).

A JSXGraph graph class under `src/graphs/compgeo/` that adapts `PointSetModel`, reused by every lesson of this family, the triangulation and sweep families, and triangle geometry. This stream owns its interface; keep it small and documented in a module comment.

1. Study first: `src/graphs/base/BaseGraph.tsx`, `GraphSession.ts`, `SceneStore.ts`, `PointCoordinateEditor.tsx`, `presets/PresetCollection.ts` and an analysis graph with a stored model and presets (`src/graphs/functions/BisectionGraph.tsx` and its host test). Follow `docs/current-architecture.md` sections *Geometry and interactive graphs*, *State and persistence* and *Preset contract*. Do not edit shared host code (`BaseGraph.tsx`, `GraphSession.ts`, lesson runtime); if the graph cannot be built without a host change, stop and report.
2. Graph behaviour: points drawn at `gridToBoard`; drag snaps to the grid on every move; click on empty board adds a point only in an explicit **Add** mode (toggle button), so touch panning and dragging never add points; selected point removed with Delete/Backspace or a Remove button; Clear button; arrow keys move the selected point by one grid step; a numeric point list (reuse `PointCoordinateEditor` if it fits) with x/y fields and an **Add point** button, so the whole workflow works without a pointer. At the point limit, Add shows a visible message and adds nothing. Polygon mode draws edges in order (closing edge when `closed`) and shows a text status "simple" / "not simple" from `polygonSimplicity` (colour is never the only signal). Optional lattice grid overlay.
3. An overlay extension point for later lessons (hull, turns, ray, trace): a typed list of overlay ids with show/hide state in the scene state, plus a way for a subclass or composition to draw an overlay from the current model. Implement only the grid overlay now; document the hook.
4. Presets: a Preset collection for the graph family storing `PointSetModel` via `parsePointSetModel`; import of invalid data shows the actionable reason (localized). Locale keys go in one new block in `sl.ts` and `en.ts`, at the same position in both, placed after the last key of the area this graph belongs to (not at the end of the file); call `t()` per AGENTS.md.
5. Ownership: every board object, listener and keyboard handler is created by the graph and disposed on scene change and unmount; no graph-global state.
6. Tests: component/host tests in the style of the bisection host test — add in Add mode only, drag snaps, arrow-key nudge, Delete, Clear, limit message, numeric add, polygon simplicity status for a bow-tie, preset restore and invalid import message, Reset, disposal (no leftover board objects or listeners after unmount), state after a language switch. Unit tests for any pure adapter code. Record observed failures under a deliberate mutation for two of the assertions.

Checks: `just unit src/graphs/compgeo` and `just unit src/compgeo`, the full unit suite once, `npx tsc --noEmit --pretty false`, production build (localization). No route exists yet, so browser smoke waits for F2b; the handler records that gap.
