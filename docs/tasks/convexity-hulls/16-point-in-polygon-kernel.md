New module `src/compgeo/pointInPolygon.ts`, independent of React, JSXGraph and localization.

1. `classifyPoint(q: GridPoint, vertices: readonly GridPoint[])` returns `{location: 'boundary'}` when \(q\) lies on an edge or is a vertex (`onSegment`). Otherwise it returns `{location: 'off-boundary', crossings, winding, evenOdd: 'inside' | 'outside', nonzero: 'inside' | 'outside'}`. The polygon is closed (the last vertex joins the first) and may be self-intersecting. Fewer than three vertices, and zero doubled area with no boundary hit, are handled and documented, not thrown.
2. **Ray and half-open rule.** The ray goes from \(q\) in the \(+x\) direction. An edge \(ab\) counts when exactly one of \(a.y > q.y\) and \(b.y > q.y\) holds, so a vertex on the ray counts only with the edge above it. The crossing must also lie to the right of \(q\), which is decided by the sign of `orient(a, b, q)` relative to the edge direction, never by a computed intersection. The winding number adds \(+1\) for an upward crossing with \(q\) left of \(ab\) and \(-1\) for a downward crossing with \(q\) right of it. State the rule in the module comment in one sentence a lesson can quote.
3. `rayCrossings(q, vertices)` returns the counted edges in order (edge index, direction \(\pm1\), and the crossing's exact \(x\) as a `rational.ts` value for drawing). It also returns the edges that touch the ray at a vertex without counting, so a graph can draw both. It uses the same rule as item 1, and `classifyPoint` uses it.
4. **Pentagram.** Export `PENTAGRAM_VERTICES`, a lattice approximation of the regular \(\{5/2\}\) star: unit-circle vertices, scaled and rounded, visited in star order. Choose the scale so the central pentagon contains lattice points well clear of every edge. A comment states that the figure is approximate and records the scale. Export `NOTCHED_PENTAGON` \((0,0),(6,0),(6,4),(3,2),(0,4)\) unless a shared constant exists; reuse one from 07 or the polygon-area Presets if present.
5. **Tests** (`pointInPolygon.test.ts`):
   - The spec's pentagon values: \((3,1)\) and \((1,3)\) have winding number \(1\) and are inside under both rules; \((3,3)\) has winding number \(0\) and is outside.
   - Pentagram: the centre has winding number \(2\), even–odd says outside and nonzero says inside; one point in each tip has winding number \(1\). Assert these by exact computation, and assert that every vertex of `PENTAGRAM_VERTICES` is a lattice point.
   - Spec acceptance 2 (a ray through a vertex gives the same answer as a nearby ray), over every vertex of the two examples and of random polygons. Write the exact formulation in the test: for example, a query on the horizontal through a vertex has the same verdict as the query moved by a small dyadic offset off that horizontal, evaluated exactly at a finer grid scale.
   - Every lattice point of every edge (by gcd stepping), and every vertex, classifies as `boundary`.
   - Brute-force reference: the angle-sum winding number (the sum of `atan2` turn angles over \(2\pi\), rounded) equals `winding` for random grid polygons up to 12 vertices and every off-boundary lattice query in their box; \(\text{crossings} \bmod 2 = \text{winding} \bmod 2\) for every tested point (acceptance 5).
   - `strictlyInsidePolygon` from 07 agrees with `classifyPoint` (nonzero rule, off the boundary) on simple polygons.
   - Observed failures under two mutations, for example `>=` for `>` in the half-open test, or dropping the boundary check.
